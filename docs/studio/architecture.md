# Claude Studio — архитектура

Целевое устройство после всех этапов. Где этап вводит часть этого устройства, он ссылается на раздел отсюда.
Что есть сейчас — [../shturm.md](../shturm.md) и [../preproduction.md](../preproduction.md).

---

## 1. Принципы

1. **Один движок.** three.js r186 + postprocessing + бумажный тулкит; редактор, черновики, ревью и рендер ролика рисуют сцену одним кодом (`buildFromScene`).
2. **Данные отдельно от кода.** Как выглядит предмет — код (префаб, пишет Claude). Где он стоит, как движется, как снята камера, какие анимации включены — данные (`scene.json`), их правят и редактор, и Claude.
3. **Всё — операции.** Любая правка документа (видео, сцены, персонажа) — операция `set/add/del/move` с автором и человекочитаемым описанием. Из операций — отмена, повтор, история и то, как агент «видит» работу автора.
4. **Время — чистая функция.** Кадр сцены в момент `t` вычисляется только из данных и `t` (ключи, клипы, шум от времени). Кадры рендерятся в любом порядке.
5. **Правки автора священны.** Всё, что автор сделал руками, помечено; агент меняет это только по прямой просьбе.
6. **Библиотека версионирована.** Сцена ссылается на конкретную версию персонажа / пропса; обновление — явное действие.

## 3. Модель данных

Все документы — JSON с `schema` (номер формата) и `rev`. Правки — операциями (раздел 5). Идентификаторы — короткие строки с префиксом типа (`o3f2a`, `k91c0`…).

Заменяет нынешний план штурма. Поля — как у плана пути «Есть идея», без удалённых частей.

### 3.3 Сцена `scene.json` — главный формат редактора

```json
{
  "schema": 1, "id": "e6640ce01", "name": "Комната зимним утром",
  "len": 10, "fps": 30,
  "world": { "fx": "dusk", "bg": "#1a1d2e", "fog": null, "env": "roomShell" },
  "camera": {
    "fov": 30, "handheld": 0.012, "focus": null,
    "keys": [ { "id": "k1", "t": 0, "pos": [0.02, 0.95, 3.0], "target": [0.14, 1.06, -0.6], "fov": 30, "ease": "io" },
              { "id": "k2", "t": 10, "pos": [0.1, 0.92, 2.78], "target": [0.2, 1.02, -0.6], "ease": "io" } ],
    "cuts": [ { "id": "c1", "t": 4.2, "name": "план 2" } ]
  },
  "lights": [ { "id": "l1", "name": "Настольная лампа", "type": "lamp", "pos": [0.6, 1.1, -0.4], "color": "#ffc36b", "intensity": 12, "flicker": 0, "keys": {} } ],
  "objects": [

      "clips": [ { "id": "c3", "t": 3.2, "dur": 1.5, "anim": "hog/scratch-head", "speed": 1, "loop": false } ],
      "pose":  [ { "id": "p1", "t": 5.4, "bones": { "armR": { "rot": 1.2, "len": 1.15 } }, "ik": { "armR": [0.52, 0.94, -0.35] },
                   "note": "тянется к кнопке, пальцы на ней", "refine": "open" } ],
      "face":  [ { "id": "f1", "t": 2.0, "dur": 1.2, "emotion": "surprised" } ],
      "facing": "camera" },
    { "id": "g1", "name": "Мебель", "type": "group", "children": ["o1", "o2", "o3"], "pos": [0, 0, 0], "rot": [0, 0, 0], "scale": 1, "keys": {} }
  ],
  "sounds": [ { "id": "s1", "t": 0.0, "src": "el:eac3fc302", "gain": 0.6, "note": "гул под всей сценой" } ],
  "markers": [ { "id": "m1", "t": 3.2, "name": "чешет затылок" } ],
  "comments": [ { "id": "n1", "target": "o7", "t": 5.4, "text": "пусть тут испуганно отпрыгнет", "by": "author", "status": "open", "mode": "do|note" } ],
  "authored": { "o7": ["keys.pos", "pose.p1"], "camera": ["keys"] }

```
- **Время.** `t` — секунды сцены. Сцена — «репетиция»: при монтаже `markers` привязываются к словам голоса, время между маркерами растягивается кусочно-линейно (раздел 3.8).
- **Ключи.** `keys.<свойство>[] = {id, t, v, ease}`, `ease`: `linear | io | in | out | hold`. Между ключами — интерполяция; до первого и после последнего — значение крайнего ключа; без ключей — статичное значение объекта.
- **Камера.** Ключи `pos / target / fov`; `cuts` — склейки внутри сцены (разные планы: камера прыгает, а не едет). `handheld` — дрожь от времени.
- **Группа.** `type: group` — объект-родитель; ключи группы применяются к детям (детские координаты — относительно группы).
  Источник правды — поле `parent` у ребёнка (S1): список `children` у группы не хранится, дерево собирается из `parent` (так одна операция переносит объект в группу).
- **Поворот** `rot = [x, y, z]` в радианах, порядок `YXZ` (сначала курс по Y, потом наклон) — удобно для карточек. Ключи поворота хранятся «развёрнутыми»:
  редактор ставит новый ключ ближе к прошлому (`unwrapAngle`), поэтому 179° → −179° идёт через 180°.
- **Логические ключи** (`hide`) не интерполируются; до первого ключа — статичное значение объекта. Цвета `#rrggbb` интерполируются.
- **Ease** хранится у ЛЕВОГО ключа и задаёт кривую до следующего; по умолчанию `io`.
- **Персонаж.** `clips` (анимации из библиотеки), `pose` (ключи позы поверх клипов: кости и цели IK; `refine: open|done` — просьба «✨ доведи»),
  `face` (эмоции), `walk: auto|off|<anim>` (при движении по `keys.pos` ходьба включается сама, фаза — от пройденного пути), `facing: camera|free|back`.
- **Звуки** — ссылки на элементы-звуки или библиотеку, с моментом и громкостью; «нет звука — подставит Claude» = комментарий `mode: do`.
- **`authored`** — пути, которые автор трогал руками. Агент их не меняет без прямой просьбы (правило вшито в промпт и проверяется валидатором операций агента).
- **Файлы рядом:** `prefabs.js` (код), `history.jsonl` (история операций), `v<N>/` (версии: копия `scene.json` + `prefabs.js` + кадры + `clip.mp4`).

### 3.4 Префабы `prefabs.js`
Код, который пишет Claude: как выглядит каждый предмет сцены. Ни позиций, ни времени сцены здесь нет.
```js
const PREFABS = {
  roomShell: { kind: 'env', build(w, o) { /* стены, пол, окно — статичное окружение */ } },
  desk:      { kind: 'card', px: [640, 512], h: 0.78, draw(g, cw, ch, T, o) { drawDesk(g, …) } },
  lamp:      { kind: 'group', build(w, o) { const G = new THREE.Group(); …; return G; }, lights: [{ type: 'lamp', at: [0, 0.4, 0] }] },
  crt:       { kind: 'model', model: 'lib:models/crt-monitor@1', matte: true },
  snowWindow:{ kind: 'card', dynamic: true, draw(g, cw, ch, T) { … метель по T … } },
};
```
- `kind`: `env` (окружение, один раз, через `world.env`), `card` (бумажная карточка — как `w.card`), `box` (коробка — как `w.box`), `group` (произвольный `THREE.Object3D`:
  всё, что `build` добавил в сцену, уезжает в объект; можно вернуть `{ obj, tick }`), `model` (glTF), `overlay` (2D поверх кадра — титр, плашка), `character` (из библиотеки — префаб не пишется, строит `rig.js`, S4).
- `home: { pos, rotY }` (S1): префаб строит предмет «по месту», как в старой сцене, а движок переносит его в начало координат объекта;
  у объекта тогда `pos = home.pos`, `rot = [0, home.rotY, 0]`. Так старые сцены переводятся без пересчёта координат и крутятся вокруг своей точки.
- `tick(T, o, root)` — анимация внутри предмета каждый кадр. Свет внутри предмета (лампа на столе, отсвет экрана) — в префабе, его цвет и яркость — `params`.
- Параметры префаб читает так: `P_(o, 'имя', по_умолчанию)` — по этим вызовам сервер строит список параметров с умолчаниями (`scene_api.prefab_info`) для панели свойств и агента.
- Префаб может читать параметры объекта `o.params` (цвет, надпись, вариант) — они в `scene.json` у объекта: `"params": { "label": "Компьютер" }`.
- Анимация «внутри» предмета (метель в окне, мигающий экран) — внутри префаба от `T`; движение предмета по сцене — только ключами.

### 3.5 Движок сцены `engine/scene.js`
```js
const S = buildFromScene(w, scene, PREFABS, LIB);   // один раз: создаёт объекты, помнит id -> THREE.Object3D
applyScene(S, t);                                    // каждый кадр: ключи, клипы, позы, лица, ходьба, facing, камера, свет
```
- Реализуется поверх `stage3d.js` (`world3d`, `card`, `model`, `lamp`…); `w.items` и `w.layout` заменяются объектами сцены.
  Каждый объект — `THREE.Group`-держатель с трансформацией из данных; `S.hold` — объекты, которые сейчас тянет мышь (ключи их не перетирают).
  `syncScene(S, rebuild)` — после структурных правок (добавить, удалить, в группу, сменить префаб / params). `sceneWorld(scene, PREFABS)` — мир целиком.
  Глобальные имена движка — с префиксом `scene…` (`sceneCamAt`, `sceneShotOf`…): в тулките `paper.js` уже есть `camAt`.
- В S1 файл лежит в `template/src/scene.js` (переедет в `engine/` в S2), тесты — `template/src/test/scene.test.js`.
- Оценка ключей — чистые функции (`evalKeys(keys, t, fallback)`), покрыты тестами (node, без браузера).
- `render_clip.js` — рендер сцены в mp4 (кадры со стенда → ffmpeg), используется для «🎞 клип сцены» и превью в библиотеке.

### 3.6 Скелет, риг, анимации

**Тип скелета** `library/skeletons/<type>.json`:
```json
{ "schema": 1, "type": "hog", "name": "Ёжик",
  "bones": [ { "id": "root" }, { "id": "body", "parent": "root", "len": 0.5 },
             { "id": "head", "parent": "body" }, { "id": "armL", "parent": "body", "len": 0.22, "limits": [-2.4, 2.4] },
             { "id": "armR", "parent": "body", "len": 0.22 }, { "id": "legL", "parent": "root" }, { "id": "legR", "parent": "root" } ],
  "slots": { "head": "head", "handL": "armL", "handR": "armR", "back": "body", "belt": "body" },
  "face": { "eyes": ["open", "half", "closed"], "brows": ["neutral", "up", "angry", "sad"], "mouth": ["flat", "smile", "open", "o", "frown"], "look": [-1, 1] },
  "ik": [ { "chain": ["armL"], "end": "handL" }, { "chain": ["armR"], "end": "handR" } ] }
```
**Персонаж** `library/characters/<slug>/character.json`: `{ id, name, skeleton: 'hog', rig: 'param'|'parts', mode: 'bend'|'pins', versions[], latest, costumes[], emotions{}, anims[] (свои, сверх типовых), tags }`.

**Два вида рига** (`engine/rig.js`), оба принимают одну и ту же позу `{ bones: {id: {rot, len, pos}}, face: {...} }`:
- `param` — процедурный рисунок с параметрами (ёжик: `drawHog` — `armL/armR`, `lenL/lenR`, `look`, `mouth`, `walk`, `backView`). Кость ↔ параметр — таблица в `skeleton.json` (`"map": {"armL.rot": "armL", "armL.len": "lenL"}`).
  Самый качественный вид для нашего ёжика; миграция — S4.
- `parts` — персонаж нарисован частями (слоями) на холстах; каждая часть — текстурированная сетка (`SkinnedMesh` на подразделённой плоскости) с весами к костям.
  `mode: 'pins'` — каждая часть на 100% одной кости (кукла на булавках, стыки спрятаны перекрытием); `mode: 'bend'` — веса плавно переходят через сустав (части гнутся).
  Веса считаются автоматически по расстоянию до костей; в будущем — ручная правка весов (как в Spine / Moho).
- **Будущее:** `rig: 'glb'` — 3D-персонаж со своим скелетом glTF; кости сопоставляются с типом скелета, клипы из glTF и из библиотеки играются одинаково.

**Анимации** `library/anims/<type>/<slug>.json` — данные, а не код:
```json
{ "schema": 1, "id": "hog/scratch-head", "name": "Чешет затылок", "type": "hog", "dur": 1.5, "loop": false,
  "tracks": { "armR.rot": [[0, 0.2], [0.4, 2.6, "io"], [1.1, 2.4], [1.5, 0.2, "io"]], "head.rot": [[0, 0], [0.5, -0.15]], "face.eyes": [[0.3, "half"]] },
  "prompt": "чешет затылок левой лапой", "by": "claude", "preview": "scratch-head.webp", "created": "2026-10-…" }
```
- Клипы наследуются всеми персонажами этого типа скелета. Циклические (`walk`, `idle`) — `loop: true`; ходьба может быть процедурной: `"proc": "gait"` (фаза от пути).
- Смешивание: на пересечении клипов — кроссфейд 0.2 с; ключи `pose` ложатся поверх клипов; IK решается последним.
- **Эмоции** — именованные наборы лица (`emotions: { surprised: { eyes: 'open', brows: 'up', mouth: 'o' } }`); дорожка `face` на таймлайне.
- **Липсинк:** громкость голоса (RMS по окнам 1/30 с, считает сервер из `build/vo/*.wav`) → `mouth: open` / `flat` с порогом и сглаживанием; включается у персонажа-рассказчика на монтаже.
- **Костюмы и пропсы:** `costumes[]` — префабы с `slot` (кепка → `head`), крепятся к кости и двигаются с ней; версия костюма независима от персонажа.
- **Paper Mario:** при `rules.paperFacing` карточка персонажа доворачивается к камере не больше `facingMaxDeg`; спина (`backView`) — только когда персонаж реально развёрнут (`facing: back` или поворот > 90°).

### 3.7 Библиотека
- `index.json`: `[{ id: 'characters/hog', kind, name, tags, latest: 4, preview, from: { video, element } }]`.
- Ссылка из сцены — `lib:<kind>/<slug>@<версия>`; без `@` — последняя (только в редакторе; в сохранённой версии сцены — всегда с версией).
- Публикация: элемент препродакшена получил ✓ → предложение «в библиотеку» (новый предмет или новая версия существующего). Агент публикует только с «да» автора.
- Обновление в сцене: «доступна v5 ёжика» → кнопка «обновить в этой сцене» (старые ролики не меняются).

### 3.8 Монтаж `video.json → montage`
```json
{ "tracks": {
    "scenes":  [ { "id": "u1", "scene": "e6640ce01", "at": 0.0, "len": 7.8, "map": [[0, 0], [3.2, "w:12"], [10, 7.8]], "trans": { "type": "slide", "dur": 0.4 } } ],
    "voice":   { "file": "build/vo/*.wav", "words": "src/vo_timing.js" },
    "captions":{ "style": "channel", "overrides": [] },
    "sfx":     [ { "id": "x1", "at": 1.2, "src": "lib:sounds/lift-door@1", "gain": 0.8, "align": "peak" } ],
    "music":   [ { "id": "mu1", "at": 0, "src": "…", "gain": 0.5, "duck": true } ],
    "overlays":[ { "id": "ov1", "at": 2.0, "dur": 1.5, "kind": "note|sticker|label", "text": "200 000 ₽", "pos": [540, 400] } ],
    "notes":   [ { "id": "r3", "at": 4.1, "text": "ёжик застрял в стене", "from": "review" } ] } }
```
- `map` — соответствие времени сцены времени ролика: пары `[t_сцены, t_ролика | "w:<индекс слова>"]`; между парами — линейно. Маркеры сцены цепляются к словам перетаскиванием.
- Из монтажа генерируется то, что сейчас пишет Claude руками: `src/scenes.js` (секции, `WT()`, `sfx(add)`), `audio.py` конфиг — функцией `montage → project` (S6). `build.sh` и рендер остаются.

## 4. Приложение

- **Оболочка** — Electron (`_studio/app`): Node уже есть в пайплайне, Rust-инструменты ставить не нужно. Запускает Python-скрипт (`server/`), открывает окно, перехватывает все хоткеи, своё меню.
- **Локальный скрипт** (Python, как сейчас): документы и операции, задачи, агент, файлы, рендер. Порт 8790, только localhost.
- **Интерфейс** (`web/`): ES-модули без сборки, свой `h()` (как сейчас), библиотеки только из `vendor/`. Экран = набор панелей; тема «профессиональная тёмная» (см. 4.1).
- Экраны: Проект (видео + библиотека + ⚙ стиль) → Видео (этапы слева направо) → Редактор сцены → Монтаж → Ревью. Библиотека — отдельный экран и боковая панель в редакторе.

### 4.1 Визуал
Нейтрально-тёмный, как Blender / Premiere: фон `#1d1d1f`, панели `#262629`, линии `#3a3a3e`, текст `#e6e6e6`, акцент `#4d9cff` (выбор), ключи `#ffcc33`, камера `#6fe0ff`,
ошибки `#ff5a5f`, агент `#b48cff`. Шрифт интерфейса — Inter / системный, 12–13 px, плотная сетка 4 px. Иконки — один набор (Lucide, MIT, в `vendor/`).
Нынешняя фиолетовая тема «Штурма» остаётся только до переезда.

## 5. Операции, история, отмена

- **Операция:** `{ op: 'set'|'add'|'del'|'move', path, value|item|id|to, by: 'author'|'claude', desc: 'ёжик: ключ позиции на 2.4 с' , batch }`.
  Движок операций — нынешний `apply_op` из `ideas_api.py` (пути через `id` в списках), вынесенный в `server/docs.py` и в `web/ops.js` (клиент применяет сразу, сервер — под блокировкой).
- **Отмена:** клиент хранит стек пачек (`batch`) с обратными операциями; Ctrl+Z — отмена пачки, Ctrl+Shift+Z — вернуть. Правка агента — одна пачка.
- **История** `history.jsonl` сцены / видео: одна строка — одна пачка `{ts, by, desc, ops}`. Агент читает хвост истории перед работой («что автор сделал с прошлого раза»).
- **authored:** операции автора над объектом добавляют путь в `authored`; операции агента по этим путям отклоняются валидатором, если в задании нет явного разрешения (`allow: ['o7.keys.pos']`).
- **Версии:** автосохранение рабочей копии (операции сразу пишутся); «Сохранить версию» (Ctrl+S) и каждая завершённая правка агента → `v<N>/` снапшот + кадры.

## 6. Агент

- **Панель агента** справа (вызов `/` или кнопка): лента «ты / Claude», у каждого ответа агента — список сделанного и «↺ отменить».
  Во время работы — живой лог шагов («читаю сцену», «добавляю ключи камеры»), поле ввода остаётся активным: сообщение уходит агенту посреди работы.
- **Комментарии на объектах и ключах:** правый клик → «💬 Claude…» → `do` (сделать сейчас) или `note` (пометка на потом / для сборки).
- **Как запускается:** Claude Agent SDK для Python (сессия с потоковым вводом: можно дописать посреди работы и прервать) или `claude -p --input-format stream-json --output-format stream-json`.
  На подписке автора, без API-ключей. Реализатор проверяет доступность на установленной версии Claude Code и выбирает; оба пути — за одним интерфейсом `server/agent.py`.
- **Инструменты агента** — не правка файлов, а команды студии (то же, что CLI, раздел 7): `scene.get`, `scene.ops` (пачка операций с `desc`), `scene.render(t)` (кадр PNG — посмотреть),
  `scene.clip()`, `lib.search/get`, `prefab.write` (правка `prefabs.js` с автоматическим рендером проверки), `anim.create`, `skeleton.propose`, `assets.search/fetch`, `sounds.search/fetch`.
  Прямой доступ к файлам — только чтение (`Read`), запись — через команды, чтобы всё попадало в историю и отменялось.
- **Модели:** по типу задачи (расстановка, ключи, мелкие правки — Sonnet; префабы, скелеты, анимации, рисование — Opus) + переключатель в панели.
- **Правила в системном промпте:** не трогать `authored` без прямой просьбы; менять библиотеку только после «да» автора; одна просьба — одна пачка; после правки — посмотреть кадр.
- **Блокировка:** пока агент работает над сценой, редактор этой сцены — только просмотр (с отменой задачи); другие сцены и этапы свободны.

## 7. CLI `studio.py`

То же, что умеет агент, — для Claude в чате разработки и для тестов:
```
studio.py channel list | use <id>
studio.py video list | new short|long "Имя" [--idea …] | show <id>
studio.py scene show <video>/<scene> | ops <video>/<scene> '<JSON-пачка>' --desc "…" | render <video>/<scene> --t 2.4 | clip <video>/<scene>
studio.py scene convert <video>/<scene>          старый element.js (+ layout/groups) → prefabs.js + scene.json (через Opus)
studio.py lib list [--kind …] | show <id> | publish <video>/<element> [--as new|<id>]
studio.py anim create <character> "чешет затылок, 1.5 с" | skeleton propose <character>
studio.py montage build <video>                  монтаж → src/scenes.js, audio → build.sh
```

## 8. Хоткеи

Объекты — как в Blender, время — как в Premiere Pro. В полях ввода хоткеи не срабатывают (кроме Ctrl+Z / Ctrl+Shift+Z / Ctrl+S / Esc). Карта переопределяется в настройках (`keymap.json`).

| действие | клавиши |
|---|---|
| выбрать / добавить к выбору / всё / снять | клик / Shift+клик / A / Alt+A |
| двигать · вращать · масштаб | G · R · S (затем X / Y / Z — ось, Shift+ось — плоскость, число с клавиатуры, Enter / клик — применить, Esc / ПКМ — отмена) |
| сбросить позицию · поворот · масштаб | Alt+G · Alt+R · Alt+S |
| дублировать · удалить · скрыть / показать всё | Shift+D · X или Delete · H / Alt+H |
| сгруппировать · разгруппировать | Ctrl+G · Ctrl+Alt+G |
| ключ на текущем времени · удалить ключ | I · Alt+I |
| показать выбранное · всё | Numpad . или F · Home |
| вид камеры · камера на этот вид («ключ с этого вида») | Numpad 0 · Ctrl+Alt+Numpad 0 |
| орбита · сдвиг · приближение | средняя кнопка · Shift+средняя · колесо (в ноутбуке: Alt+ЛКМ орбита, как в опции Blender) |

| отмена · вернуть · сохранить версию | Ctrl+Z · Ctrl+Shift+Z · Ctrl+S |
