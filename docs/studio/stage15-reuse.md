# S15. «Уже было» — ревью найденных ассетов перед препродакшеном

**Статус: сделано 5 окт 2026** (код — `server/reuse_api.py`, `web/ui/reuse.js`; итог и отличия от плана — §8).

**Зачем.** Правило канала (`memory/rules.json` → m53a8042, автор): «Прежде чем создавать новый ассет, проверь, не было ли его раньше». Пока это только строка в промпте, и модель может её пропустить. Сейчас «✨ Накидать» видит только элементы своего видео. В итоге Гейб Ньюэлл, уже нарисованный в ролике про Valve, будет нарисован ещё раз.
**Что делаем.** Проверку проводит сервер, а не модель по памяти: отдельный шаг поиска по библиотеке и прошлым видео. Пока автор не согласует находки, черновики найденных элементов не рисуются. Это одна из фишек Studio.

Решения автора (5 окт 2026):
- **где искать** — библиотека канала и утверждённые ✓ элементы прошлых видео (в том числе не опубликованные); если взят элемент из прошлого видео, он сам публикуется в библиотеку;
- **когда** — сразу после «✨ Накидать»; «✨ Сделать всё» не трогает элементы, по которым ещё нет решения;
- **действия** — «Взять как есть» / «За основу» / «Сделать новый»;
- **окно** — поп-ап поверх препродакшена.

## 1. Поток

```
✨ Накидать ──► новые элементы (status '', libMatch.state = 'wait')
      │
      └─► задача libmatch (Sonnet) ──► находки в e.libMatch.found
                                   ──► поп-ап «Нашлось в библиотеке»
                                         │
     Взять как есть ─────────────────────┤ элемент = копия предмета библиотеки, ✓, без черновика
     За основу ──────────────────────────┤ копия → задача element «поправь под это видео» (vN+1)
     Сделать новый ──────────────────────┘ обычный черновик
Нет находок → libMatch.state = 'none', элемент идёт в работу как обычно.
```

## 2. Поиск (задача `libmatch`)

1. **Каталог** собирает сервер (`studio_api.reuse_catalog(video)`):
   - строки `library/index.json`: `char`, `prop`, `sound` и 3D-модели;
   - `candidates()`: утверждённые ✓ элементы других видео канала, которых ещё нет в библиотеке;
   - у каждой строки есть ref (`lib:characters/gabe@2` или `el:<видео>/<эл>@vN`), вид, название, описание, теги, превью, 2D/3D и видео, откуда предмет.
2. **Предфильтр без Claude.** По каждому новому элементу берутся строки того же вида, у которых пересекаются слова в названии, описании или тегах (с учётом ё/е и основы слова). Плюс до 30 строк того же вида целиком, чтобы Claude нашёл и непохожие по словам («ЭЛТ-монитор» ↔ «Монитор Бол-сой»).
3. **Claude (Sonnet)** получает список новых элементов и каталог. По сомнительным находкам он через Read смотрит превью. Ответ — JSON по схеме:
   `{matches: [{el, ref, score 0–1, why, diff, suggest: 'as-is'|'base'}]}`
   - `why` — почему это тот же предмет;
   - `diff` — чем находка отличается от нужного в этом ролике; при «За основу» это готовая правка.
   - В выдачу попадают находки со `score ≥ 0.5`, не больше трёх на элемент.
4. Результат пишется в `e.libMatch = {state: 'found'|'none', found: [...], at}`. Если находки есть, в препродакшене открывается поп-ап.

**Кого проверяем.** Персонажей, пропсы и звуки — для них есть библиотека. Локации и эффекты — см. открытые вопросы (§6).

## 4. Что делает каждое действие (`POST /api/lib/reuse`, CLI `lib reuse <видео> <эл> as-is|base|new [ref]`)

- **Как есть.** Если ref вида `el:`, предмет сначала публикуется в библиотеку (`publish`). Затем `import_to_video` заливает его в **тот же** элемент, а не создаёт новый: остаются id, name, why и связи `uses` у сцен. Элемент получает `status: ok`, `lib: {id, v}`, `by: 'lib'`. Черновик не рисуется.
- **За основу.** Та же копия, но со `status: ''`. Сразу ставится задача `element` с правкой из `diff` и пометкой «в библиотеке — основа». Черновик vN+1 рисуется от кода находки. Пропсы 3D остаются 3D.
- **Новый.** `libMatch.pick = 'new'`, элемент идёт в обычный поток. Повторно для него поиск не запускается.
- Решение записывается в `e.libMatch.pick = {how, ref, at}`. Его видно на карточке («📚 из библиотеки: Гейб v2») и его можно отменить, пока черновик не утверждён.

## 5. Удержание в очереди

- `doAllTodo` (`web/ui/preprod.js`) пропускает элементы с `libMatch.state ∈ {wait, found}` и без `pick`.
- `_waits_for` (`ideas_api.py`) держит задачи `element` / `make3d` таких элементов на сервере. Это нужно на случай, если запуск пришёл не из «Сделать всё». В статусе задачи пишется «ждёт решения по библиотеке».
- Сцены и локации и так ждут всех персонажей и пропсов видео, поэтому подождут и это решение.

## 6. Открытые вопросы (рекомендации)

1. **Локации и эффекты.** В библиотеке их нет. Рекомендация: v1 — персонажи, пропсы, звуки. Локации и эффекты из прошлых видео показывать в том же окне только с действием «За основу» (копия `scene.json` / кода) — вторым этапом.
2. **Другие входы.** CLI `add-elements` (агент, automontage): поиск запускается так же, `src.pending` ждёт решения. Быстрый монтаж (`fastmontage`) добавляет элементы задним числом, поэтому поиска там нет, но есть кнопка «🔎 Проверить библиотеку».
3. **Кнопка «🔎 Проверить библиотеку»** в шапке препродакшена — запускает поиск заново по элементам без черновика и без решения.
4. **Правило m53a8042 остаётся** в памяти канала. Дополнительно в `element_spec` добавляется строка «найденное в библиотеке уже согласовано автором — не рисуй с нуля».

## 8. Как сделано (5 окт 2026)

- **Сервер** — `server/reuse_api.py`: `catalog` (библиотека + ✓ элементы прошлых видео, служебная «🛠 Мастерская» — нет), `check` (метка `wait` + задача `reuse` в очереди),
  `spec`/`apply` (промпт Sonnet, ответ -> `libMatch`), `holds` (удержание черновиков), `pick`/`undo`, HTTP `/api/lib/reuse[/check]`, CLI `lib reuse|reuse-check|reuse-catalog`.
  Задача называется `reuse` (не `lib…`: всё, что начинается на `lib`, уходит в studio_api.run_job). Запуск после «Накидать» — `ideas_api.run_action`;
  после CLI `add-elements` — запрос к запущенной Studio (`_cli_reuse`, задача из процесса CLI умерла бы с ним); `--no-reuse` — без поиска.
- **«Как есть» / «За основу»** заливают предмет в ТОТ ЖЕ элемент: `studio_api.import_to_video(…, into=eid, status)` — новой версией после его черновиков.
  «За основу» с «отличием» кладёт его правкой в `fx.main.notes` и ставит задачу `element` от скопированной версии (персонажа со скелетом — нет: правка в библиотеке).
- **Свой ассет автора** (📎, `own[]` — например, Гейб в «Valve» — фото-вырезка по 11 состояниям) — тоже в каталоге. Берётся копией картинок состояний в files видео;
  в библиотеку такие пока не публикуются (библиотека не хранит `own[]`) — отличие от §4.
- **Звук** из прошлого видео берёт слои со сдвигом и громкостью из исходного элемента; из библиотеки — файлы версии (сдвиг 0).
- **Удержание** не действует в автомонтаже (автора рядом нет) и при зависшем поиске (`wait` без живой задачи `reuse`). Сцена ждёт, пока кто-то из её состава ждёт решения.
- **Окно** всплывает само при входе в препродакшен, если есть нерешённые находки, которых в этой вкладке ещё не показывали (`Reuse.shown`); слой выше панели Claude (`.reuse-modal`, z 970).
- Строка в `element_spec` не понадобилась: правка «за основу» идёт обычным потоком «Поправить».
- **Часть 2 (5 окт 2026): локации, сцены и эффекты.** В каталог попадают сцены, локации и эффекты прошлых видео: утверждённые ✓ или уже собранные в редакторе сцены (`stage.work`). Взять их можно только «За основу» (`BASE_ONLY`; в окне — «За основу / Новый»).
  `_draft_into` копирует последний черновик с кодом (`element.js`) новой версией элемента (`renders[].reuse = ref`). Если сцену потом доводили в редакторе, правка даёт ссылку на её `scene.json` / `prefabs.js` и кадр. Затем ставится задача `element` «подгони под ролик»; дальше сцена сама уходит в редактор, как новая. Редактор не копируется: `scene.json` ссылается на элементы того видео.
- Порог находки — 0,6 (на 0,5 было много шума вроде «Стив в пижаме» ≈ «ёжик в пижаме»). Claude иногда пишет в `el` «id · название» — `apply` берёт только id.
- CLI `lib reuse` и `lib reuse-check` работают через запущенную Studio (`_studio_post`, `_cli_reuse`): задача Claude, поставленная из процесса CLI, умерла бы вместе с ним.
- Проверено на видео «Проверка: уже было» (261005-3600): Гейб найден в «Valve» (85 %), ЭЛТ-монитор — в библиотеке (`lib:props/elt-monitor-bol-soi@3`, 3D),
  «Накидать» по кабинету разработчика — поиск запустился сам, готовое нашлось для 5 из 7 пропсов; «Как есть», «Передумать», «За основу», удержание черновика — работают.
