# S16. «📐 По референсу» — наша история в подаче чужого шорта

**Статус: сделано 5 окт 2026** (код — `server/refbase_api.py`, `refs_api.py` (role, run_base), `refvideo.base_extras`, `web/ui/beatmap.js`; итог и отличия от плана — §10; макет — [stage16-refbase-mockup.html](stage16-refbase-mockup.html)).

**Зачем.** Автор находит в TikTok или Shorts ролик с цепкой подачей и хочет рассказать свою тему так же, «переложить на рельсы»: те же биты в том же порядке и в тех же пропорциях, те же приёмы (хук-обвинение, перечисление на три, «но есть нюанс» на 2/3, кода). Слова — про нашу тему, но близко к оригиналу.
Сейчас референс в брифе — только «материал для вдохновения»: агент сценария берёт из него факты, а подачу ведёт по нашему стайл-гайду.

Решения автора (5 окт 2026):
- **точность** — скелет и приёмы: биты, их порядок и доли времени, риторические приёмы, длина фраз, связки. Текст про нашу тему, но по подаче близко к оригиналу;
- **что переносим** — только текст и ритм: голос **и текст на экране** (подписи, «жди концовку», заголовок над видео). Картинку и монтаж придумываем сами, как обычно;
- **до сценария** — карта «их бит → наш бит», автор её правит и утверждает, по ней пишется сценарий;
- **конфликт с гайдом** — референс главнее полностью, включая CTA и мораль, если они в нём есть;
- **длина** — как в брифе: биты растягиваются или сжимаются пропорционально;
- **где** — поле в попапе «новое видео» и кнопка «📐 За основу» у референса в брифе (данные одни).

## 1. Поток

```
Попап «новое видео»: 📐 Референс подачи ─┐
Бриф: «📐 За основу» у референса ─────────┴─► refs[].role = 'base' (один на видео)
        │
        └─► разбор base (refvideo.py, режим base): whisper со словами, кадры чаще, words.json
                 │
Сценарий → «📐 Разложить референс» ─► задача beatmap (Opus, 🌐) ─► video.json → beatmap
                 │
        Окно «Сценарий», вкладка «📐 Карта подачи»: автор правит «наш бит», пины-заметки, «✨ Переразложить»
                 │
        «✓ Утвердить карту и написать» ─► агент mode script (+ блок «по референсу») ─► script.md
                 │                                         шапка: «по референсу: <ссылка>»
        check_script.py: при «по референсу» нормы гайда (темп, «Но», CTA, кода) — справкой, а не ❌;
                         вместо них — сверка с картой (биты, доли времени, длина фраз)
```

## 2. Данные

- `refs[].role` — `'base'` или нет поля. Base может быть только один: если отметить другой референс, у прежнего роль снимается (op `set`).
- `refs[].parse` у base дополнительно содержит: `words` (путь к `words.json` — `[{t0, t1, w}]`), `shots` (путь к `shots.json` — склейки по ffmpeg `scene`, для ритма), `frames[]` (кадры каждые 0,5 с для роликов до 90 с, иначе 1 с; листы 5×4 с таймкодом на кадре — по ним Claude читает текст на экране).
- `video.json → beatmap`:
  ```
  beatmap = {
    ref: 'r1a2b3c', status: 'draft'|'ok', at, okAt,
    lenRef: 34.2, lenOur: 45,             // длина референса и брифа -> коэффициент для таймкодов
    rhythm: {wps: 3.1, phrase: 7.4, pauses: 2},   // слов/с, слов во фразе, паузы > 0,6 с — из words.json
    summary: 'Формат «это Джон…»: …',     // 2–3 строки: в чём фишка подачи
    beats: [{
      id, t0, t1,                          // таймкоды референса
      fn: 'хук-обвинение',                 // функция бита
      device: 'обращение на «вы» + число лет',   // приём
      vo: 'You've been brushing your teeth wrong for 10 years',   // как сказано (оригинал)
      voRu: 'Вы 10 лет чистите зубы неправильно',                  // перевод, если язык не русский
      screen: 'ЖДИ КОНЦОВКУ',              // текст на экране, '' если нет
      words: 9,                            // длина фразы
      our: { vo, screen, note },           // наш бит — правит автор
      ot0, ot1,                            // наши таймкоды (пропорционально lenOur)
      fx: { notes: [{id, text}] },         // правки автора к биту для «✨ Переразложить»
      lock: true                           // автор правил руками — Claude не трогает
    }],
    fx: { notes: [] }                      // правки «в целом»
  }
  ```
- Писать — только операциями (`set/add/del`), как везде; CLI: `studio.py beatmap show|run|ok <видео>`.

## 3. Разбор base-референса (`refvideo.py`, `refs_api.py`)

1. Голос — всегда faster-whisper (`small`, CPU) с `word_timestamps=True`, даже если есть субтитры: нужен ритм, а не только текст. `transcript.txt` для base — по фразам с таймкодом `[0:03.4]`, а не абзацами по 30 с.
2. Кадры — `frames/f###.jpg` и листы `beat_sheet*.jpg` с таймкодом в углу кадра (drawtext). Для шорта до 90 с — шаг 0,5 с.
3. Склейки — `ffmpeg select='gt(scene,0.3)'` → `shots.json` (нужны только для ритма: «склейка на каждом бите»; монтаж мы не переносим).
4. Ролик без голоса (только текст и музыка) — нормальный случай: биты строятся по тексту на экране и склейкам.

## 4. Задача `beatmap` (`ideas_claude.py`, Opus, 🌐)

Вход: расшифровка со словами, листы кадров с таймкодами, `info.json`, бриф (тема, идея, ответы автора, длина), ресерч, если есть. Read — к листам и файлам; WebSearch — найти факты для нашей стороны.
Что делает:
1. Режет референс на биты по смыслу (обычно 6–14 на 30–60 с), для каждого: функция, приём, как сказано, текст на экране, длина фразы.
2. В `summary` — в чём фишка подачи одной-двумя фразами.
3. Под каждый бит пишет **наш бит**: то же место, тот же приём, та же длина фразы (±20 %), та же связка («Но есть нюанс» остаётся «Но есть нюанс»). Числа, имена и факты — наши и только из брифа / ресерча / найденного в 🌐 (с источником в `note`). Фактические утверждения референса к нам не переносятся.
4. Бит, которому в нашей теме нечего поставить, — `our.note: 'нет пары: …'` с вариантом, автор решит.
5. «✨ Переразложить» — новая версия карты: биты с `lock` не трогает, правки `fx` применяет и снимает.

Схема JSON: `{summary, rhythm, beats: [{t0, t1, fn, device, vo, voRu, screen, words, our: {vo, screen, note}}]}`; `ot0/ot1` считает сервер.

## 5. Интерфейс

- **Попап «новое видео»** (`web/ui/videos.js`): под полем «Референсы» — поле «📐 Референс подачи — взять за основу» (одна ссылка, подсказка «ролик, в подаче которого расскажем нашу историю»). Ссылка уходит в `refs` с `role: 'base'`.
- **Бриф** (`Plan.refRow`, `web/idea.js`): у видео-референса кнопка «📐 За основу» / «📐 Основа подачи ✓» (снять). Base показывается первым и с плашкой.
- **Шаг «Сценарий»** (`workspace.js`): если есть base и карта не утверждена, кнопка — «📐 Разложить референс» (или «Открыть карту»), а не «Написать».
- **Окно «Сценарий»** (`web/ui/script.js`): первая вкладка «📐 Карта подачи», если есть base:
  - сверху — плеер референса (`<video>` из `files/ref_<id>/video.mp4`), фишка подачи `summary`, ритм (слов/с, фраза, длины: 34 с → 45 с);
  - таблица битов: слева «их бит» (таймкод — клик проматывает плеер; функция, приём, цитата + перевод, текст на экране), справа «наш бит» (поля голос и текст на экране, правка сразу ставит `lock`), 📌 — заметка к биту;
  - внизу — правки «в целом», «✨ Переразложить (N правок)», «✓ Утвердить карту и написать сценарий».
  - После сценария вкладка остаётся: справка, что откуда.
- Макет — [stage16-refbase-mockup.html](stage16-refbase-mockup.html).

## 6. Сценарий по карте (`agent.py`, mode `script`)

Если `beatmap.status == 'ok'`, к промпту режима добавляется блок «ПО РЕФЕРЕНСУ»:
- одна сцена сценария на бит (короткие соседние биты можно слить в сцену, но не переставлять); таймкоды — `ot0–ot1`;
- **VO** — `our.vo`, доводить можно только до звучания, смысл и длину фразы не менять; **Текст:** — `our.screen`; **Картинку** придумывает сам (наш стиль, препродакшен);
- шапка: `по референсу: <ссылка>`, `rate:` подобрать под `rhythm.wps` референса (а не под 2,65);
- стайл-гайд канала — только там, где референс ничего не диктует; CTA и мораль из референса остаются;
- ресерч — как обычно; таблица в конце ответа — «бит референса → сцена».

## 7. Проверка (`template/check_script.py`)

При строке `по референсу:` в шапке:
- нормы гайда (темп 2,65, «Но», CTA, сухая кода, длина фраз ~10) — ℹ справкой, не ❌;
- новые проверки: число сцен ≈ числу битов карты; доля времени каждой сцены отклоняется от бита не больше чем на ±30 %; средняя длина фразы — в ±25 % от референса; текст на экране есть там, где он был у референса.
Карту скрипт берёт из `refs/штурм.json` → `beatmap` (экспорт `produce` / `set_brief` кладёт её туда).

## 8. Права

Переносим подачу (структуру и приёмы), а не чужие факты и не чужие кадры. В «Права» упаковки — строка «Формат подачи по мотивам: <автор>, <ссылка>» (из `refs[].role == 'base'`).

## 9. Этапы

1. Данные и разбор: `role`, режим base в `refvideo.py` (слова, кадры, склейки), CLI.

## 10. Итог (5 окт 2026) и отличия от плана

- **«💡 Похожие темы»** (добавлено по просьбе автора): поле «📐 Референс подачи» в попапе + кнопка «💡 Похожие темы» — видео заводится сразу (имя «Тема по референсу», если пусто),
  ссылка становится референсом подачи, задача `reftopics` (Opus, 🌐) смотрит ролик и даёт 6 тем канала в той же механике (`refTopics.items`: название, тема, механика, почему зайдёт, факты со ссылками, риск);
  клик по теме кладёт название, тему и «Угол» в бриф → «Далее» (вопросы) → «Создать» → проект и сразу карта подачи. «Ещё темы» — следующая шестёрка без повторов.
- **Бюджет слов:** при длине брифа ≠ длине референса у бита `target = words × k` (k = наша длина / их длина); при k < 0,75 Claude сливает короткие соседние биты и может убрать второстепенный
  («убрать: почему»), при k > 1,35 — добавляет фразу того же приёма. Первый прогон без бюджета (107 → 45 с) дал текст вдвое длиннее брифа.
- **TikTok / Instagram:** yt-dlp без имитации браузера получает «Unexpected response» — нужен `curl_cffi` (`pip install curl_cffi`), `refvideo.ytdlp` сам добавляет `--impersonate chrome`.
- **Референс с диска:** видео копируется в `files/<id>/ref_<rid>/` (до 300 МБ), иначе плеер карты не может его взять с сервера.
- **check_script.py:** бит ищется окном с наибольшим совпадением основ слов (первое общее слово давало ложное «переставлены»); `BEATMAP_CHECK = N` — студия обновляет `check_script.py` проекта, если он старее шаблона.
- Агент сценария получает блок «📐 ПО РЕФЕРЕНСУ» только при утверждённой карте; утверждение (или новая версия) перезапускает сессию агента.
- Заодно: плитки визуала в попапе «Новое видео» (глобальный стиль кнопки сжимал превью в 0 и выталкивал название) — `.lk-pk { align-items: stretch; white-space: normal }`.

## 11. Режимы: длинное ↔ шортс (5 окт 2026, по просьбе автора)

Режим карты выбирается сам по длинам (длинное — больше 3 мин, как в check_script) или автором (переключатель «Режим» на вкладке карты → `video.json → beatmapMode`):
- **Один в один** — как раньше; если ролик длинный, биты группируются в главы (`beats[].chapter`, 3–7 глав; главы YouTube референса — из info.json), бит ≈ 15–40 с.
- **Длинное → шортс (сжатие)** — решение автора: «формула всего ролика». Claude смотрит длинное целиком и собирает шортс на 6–14 битов из его хука, фирменных приёмов, поворотов и коды;
  у бита t0–t1 — откуда в референсе взят приём (любое место), порядок битов — наш.
- **Шортс → длинное (растяжение)** — решение автора: «бит шортса = глава». Хук шортса → холодное открытие и обещание, его кода → финал; внутри главы 3–8 наших битов повторяют приём своего бита шортса; нормы longform.md.

Общее: у бита `odur` — его секунды у нас (Claude), сервер ставит `ot0/ot1` подряд и подравнивает сумму под бриф; бюджет слов `target = odur × темп референса`.
Сменили режим — «Переразложить» раскладывает с нуля (прошлая версия и 🔒 другого режима не передаются). Длинный референс: в промпт — первые 15 000 знаков фраз, остальное Claude дочитывает файлом
(`phrases.txt`); whisper по словам — `small` до 20 мин, дальше `base`; кадров с таймкодом не больше ~240. Агент сценария ставит «## Глава N. …» по главам карты, check_script сверяет число глав (±1), `BEATMAP_CHECK = 3`.

## 12. Поп-ап: два пути и лёгкие плитки визуала (5 окт 2026)
- Автор: ресерч идеи по референсу — отдельный путь, а не кнопка в брифе. В поп-апе сверху «Есть идея | 🔎 Ресерч по референсу»; во втором — ссылка, «Что ищем» (→ `params.hint`), «💡 Найти темы», карточки тем;
  клик по теме переключает на «Есть идея» с заполненным брифом (ролик остаётся референсом подачи). Закрыли до выбора темы — клик по видео в списке вернёт к темам (`NewVideo.resume`).
- Поп-ап глючил: превью визуалов грузились все сразу, а во время ресерча поп-ап перерисовывался каждые несколько секунд и грузил их заново. Теперь у плитки палитра (или ▶),
  картинка и видео подгружаются только при наведении (`Looks.picker`), плитка 3:2; перерисовка поп-апа во время ресерча — только в пути «Ресерч» и только при смене видимого.
