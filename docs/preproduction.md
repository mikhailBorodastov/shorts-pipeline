# Препродакшен — спецификация

Состояние на 30.09.2026. Код: `_studio/server/` (сервис «Штурм идей»), движок: `_studio/template/src/` (`stage3d.js`, `lib.js`), тулкит: `stands/paper.js`.
Общий обзор сервиса — [shturm.md](shturm.md). Этот документ — про главный этап: препродакшен.

---

## 1. Зачем

Ролик начинается не со сценария, а с мира. К моменту, когда пишется сценарий и собирается анимация, у Claude уже должно быть почти всё:
каждая локация, каждый персонаж и предмет, каждый звук — нарисованы черновиками, согласованы с автором и лежат в проекте как ТЗ и стартовый код.

Что это даёт:
- **Автор решает до работы, а не после.** Правки «лифт не такой», «звук не тот» случаются на черновике за минуты, а не на собранном ролике через пересборку.
- **Реализатору не нужно угадывать.** У каждого ассета есть README-ТЗ, черновик, код, требования «для финала», файлы звуков и лицензии.
- **Сценарий пишется из готовых кубиков.** Сцены сценария строятся из локаций препродакшена, «Картинка» — из его элементов.

Пример, с которого всё началось (хоррор в детской поликлинике): локации — регистратура, лифт, коридор запретного этажа, развилка, кухня-флешбэк;
пропсы — бахилы, таблички, толпа, урны, скамейки, двери, кварцевая, текстуры пола и стен, лампы; персонажи — ёжик, мама, медсестра-монстр;
звуки — двери лифта, гул лифта, лампы дневного света, фоновая музыка.

## 2. Место в пути

Путь «Есть идея» (`flow: idea`, вкладки из `web/ref.json → flows.idea`):

```
💡 Идея  →  ❓ Вопросы и биты  →  🎯 Смыслы и название  →  🎬 ПРЕПРОДАКШЕН  →  🏆 Обложка  →  🚀 В работу  →  📈 Итоги
идея, контекст,   15–20 вопросов Claude,   4 угла атаки,            сцены, персонажи,    обложка и       проект из шаблона,
видео/картинки    ответы автора = решения,  без 7 вопросов           пропсы, звуки        первый кадр     refs/препродакшен/
                  биты + ✨ челлендж
```

Старый путь «💡 Штурм идей» (`flow` нет) препродакшена не имеет, но штурм с выбранной идеей переводится на новый путь кнопкой «🎬 → препродакшен».

## 3. Модель данных

Всё лежит в документе штурма `_ideas/plans/<id>.json` (правки — только операциями `set/add/del/move`, см. [shturm.md](shturm.md#документы-и-операции)).
Уровень штурма: `elements[]` и `engine: '2d' | '3d'` (движок сцен ролика).
Полная схема — в шапке `ideas/preprod.py`, здесь — с объяснениями.

### Элемент `elements[]`

| поле | что это |
|---|---|
| `id`, `kind` | `char` персонаж · `prop` пропс/реквизит · `scene` сцена-локация · `sound` звук. **Порядок работы именно такой**: сцены после тех, кто в них стоит |
| `name` | название. По нему работают @-ссылки, поэтому переименование переписывает все `@[старое]` в штурме |
| `desc`, `why` | «как выглядит / звучит» и «где в ролике» |
| `status` | `''` предложен · `ok` утверждён · `drop` не нужен (в экспорт не идёт) |
| `by` | `claude`, если элемент предложил Claude |
| `refs[]` | референсы автора `{id, img, note}`; из поиска ассетов — ещё `src` (страница) и `asset` (`<источник>:<id>`) |
| `renders[]` + `render` | версии черновика и выбранная (см. ниже) |
| `fx.main` | правки **к следующему** черновику: `notes[{id, text}]` («в целом», по пункту на Enter), `pins[{id, x, y, text}]` (x, y — доли кадра); старое поле `text` тоже читается |
| `final[]` | «🎬 Для финала» `{id, text, x?, y?}` — что автор хочет от ассета **в готовом ролике**; x, y — зелёный пин на утверждённом черновике |
| `uses[]` | только у сцены: id персонажей и пропсов в ней («Что в сцене») |
| `assets[]` | бесплатные ассеты, взятые «в работу» (раздел 8) |
| `picks[]` | что предложил Claude в «✨ Подобрать» ассеты — строки поиска + `{pid, why, use: work/ref}`; берёт автор |
| `aask` | «Что нужно» из ассетов — подсказка для Claude |
| звук: `sounds[]`, `mix[]`, `mixNote`, `sound`, `ask`, `q` | кандидаты, слои микса, как свести, первый слой (совместимость), «какой нужен», последний поисковый запрос (раздел 9) |

### Черновик `renders[]`

`{id, v, dir, img, extra[], fn, three, summary, note, feedback, fx, ts}` + у 3D-версий из редактора `layout`, `groups`, `by: 'layout'`.
- `dir` — папка версии `_ideas/render/<plan>/<element>/v<N>/` с `element.js` (код) и PNG; `img` / `extra` — копии кадров в `files/<plan>/`.
- `fn` — главная функция: `drawX` у 2D, `buildX` у 3D-сцены.
- `feedback` — текст правок, по которым сделана версия (пины и «в целом»); у версий редактора — «✋ расстановка: …».
- `three` — черновик на 3D-стенде (сцена); `three3` — 3D-пропс (S3): `prefab.js` вместо `element.js`, `img` — лист четырёх ракурсов, `how` — способ.
- У персонажа и пропса есть `dim: '2d' | '3d'` (S3, пока 3D — только пропсы): 2D и 3D-версии одного пропса живут рядом, карточка показывает выбранные переключателем.

### @-ссылки

В любом текстовом поле страницы «@» открывает список элементов (↑↓, Tab/Enter — вставить, Esc), в текст пишется `@[Название]`
(регистр и «ё» не важны, `preprod.MENTION`). Что это значит:
- у сцены все упомянутые персонажи и пропсы входят в её состав (`preprod.cast_of` = `uses` + @);
- промпты раскрывают ссылки: Claude получает черновик и код упомянутого элемента (`preprod.element_brief`);
- в экспорте ссылки становятся ссылками на папки элементов (`preprod.linkify`), в README — «Отмечено через @» и «Упоминается в».

## 4. Жизненный цикл элемента

```
✨ Накидать / + вручную  →  референсы, описание  →  🎨 Нарисовать черновик (Opus)  →  пины и «в целом»  →  Поправить (vN+1)  →  ✓ Утвердить
                                   ↑ 📦 ассеты, ✨ Подобрать                             ↓ (3D) ✋ Расставить → vN+1 без Claude
                                                                                          ✓ → зелёные пины и пункты «🎬 Для финала»
```

1. **Появление.** «✨ Накидать» (`elements`, Sonnet, medium): Claude читает идею, ответы, биты, смыслы и предлагает элементы по всем типам
   (или по одному типу; можно подсказать «чего не хватает»). У новых сцен сам заполняет `uses` по названиям персонажей и пропсов.
   Автор добавляет свои. CLI: `add-elements ID scene|char|prop|sound "название | описание" …`.
2. **Материал.** Референсы (Ctrl+V, перетаскивание, 📎, 🔎 — поиск картинок прямо в приложении (Яндекс Картинки без ключа, свободные CC), клик — в референсы; Google — окном, оттуда перетащить), описание, «где в ролике», 📦 бесплатные ассеты (раздел 8).
3. **Черновик.** «🎨 Нарисовать черновик» (`element`, Opus 5.5, 3–10 минут) — раздел 5.
   Сцену без черновиков её состава Claude рисует только после подтверждения: он нарисует их прямо в сцене по описанию.
4. **Правки.** Клик по картинке — красный пин с текстом; «в целом» — стек пунктов (Enter — следующий, Backspace в пустом — удалить).
   «Поправить (N)» — новая версия **от кода прошлой**: Claude получает прошлый `element.js`, PNG с номерами пинов (`pins.png`) и список правок,
   меняет только то, о чём просят. Отправленные пункты снимаются, их текст остаётся в `renders[].feedback`. Все версии остаются, переключаются кнопками vN.
5. **Утверждение ✓.** После него клик по черновику ставит **зелёный** пин «для финала» (переключатель «✏️ правка черновика / 🎬 для финала»).
6. **Для финала.** Черновик — не финал. Пункты `final[]` — прямые требования к готовому ассету («снег налипает на @[Табличку трассы]»),
   их обязан выполнить реализатор. Пины рисуются на `final_pins.png` в экспорте.

## 5. Черновики: стенды и контракты

Claude пишет `element.js`, сам рендерит его `node render_shot.js …&parts=element`, смотрит PNG (Read) и правит 2–4 прохода.
Задача — `ideas_claude.element_spec`, инструменты: Read/Write/Edit/Glob/Grep и единственная команда `node render_shot.js`.

### 2D — `stands/page.html` (персонажи, пропсы, сцены при `engine: '2d'`)

```js
const PICS = { r1: '/files/<plan>/7.png' };            // картинки -> IMG.r1 (вырезки photo / sticker)
function drawLiftPanel(ctx, x, yНог, рост, o = {}) {…} // сам элемент: отдельная функция, её переносят в scenes.js
const ELEMENT = { t: 0.6, draw(ctx, T) { … } };        // лист-витрина 1080×1920 (раскладка по типу — SHEETS в ideas_claude.py)
```
Листы: персонаж — крупно в рост + 3 позы/эмоции; пропс — крупно + состояния; сцена — кадр 9:16 с ёжиком для масштаба.
Тулкит — `paper.js`: `cut/torn/note/photo/sticker/label/scrawl`, `drawHog(ctx, x, yНог, рост, {kind, look, mouth, armL/R, walk, backView…})`; хелперы — `engine/lib.js`.

### 3D — `/tpl/stand3d.html` (сцены при `engine: '3d'`)

Стенд лежит в `stands/stand3d.html`, но отдаётся как `/tpl/stand3d.html`, чтобы `vendor/` шаблона находился.
```js
const PICS = { r1: '/files/…png' };                    // spriteCard, текстуры
const MODELS = { m1: '/files/<plan>/assets/<id>/x.glb' }; // glTF из ассетов -> w.model('m1', {...})
const WORLD = world3d({ fx: 'night'|'dusk'|'day', build(w) { buildReception(w) }, update(w, lt, D, T) { w.camKeys(…) } });
const ELEMENT = { t: 0.6, len: 6, draw(ctx, T) { WORLD.draw(ctx, T, 4, T); } };   // len — петля живого просмотра
```
Правила из промпта: локация — отдельной функцией `build…` (переносится в ролик); персонажи и пропсы состава — картонные карточки с их `drawX`
из их `element.js` (не перерисовывать), ёжик — `hogCard`; **каждому предмету `name`** (для элементов — их название), составной предмет —
`THREE.Group` + `w.add(group, pos, 'Имя')`; сцена собрана со всех сторон (автор крутит камеру); двигающееся — от своей базовой точки в `update`.
Кадры: `element.png` (T=0.6), `element_0.2.png`, `element_2.5.png`.

### 3D-пропс — `/tpl/stand3d.html?prop=…` (пропсы при `dim: '3d'`, S3)

Формат, движок `engine/props3d.js`, поворотный стол, пины на модели, Blender — [studio/stage3-props.md](studio/stage3-props.md). Коротко: Claude пишет `prefab.js`
(`prop3d({ name, h, params, build(w, o) {…} })` из фигур `P3.*` и наклеек, или `model.py` для Blender → `model.glb` + детали), снимает четыре ракурса `render_prop.js`;
автор крутит пропс и ставит пины прямо на модель, «Поправить» делает vN+1. Утверждённый — в библиотеку, в сцене редактора — «↔ Заменить на 3D-пропс…» (`lib:` / `el:`).

### Как Claude получает контекст (промпт `element_spec`)

описание, «где в ролике», стиль канала · референсы автора (пути для Read) · **ассеты в работе** (`preprod.assets_brief`: файл, превью, как подключить) ·
**состав сцены** с черновиками, кодом и ассетами каждого · уже нарисованные элементы ролика (общий стиль) · `element_brief`: «для финала» + @-ссылки ·
идея ролика · правки (пины с координатами, `pins.png`, пункты «в целом») · блок расстановки автора, если он есть в коде · контракт стенда.

## 6. 3D-просмотр и редактор расстановки

«🧊 Смотреть в 3D» и «✋ Расставить» открывают стенд с `&view=1&edit=1&key=…&el=…&base=…` в окне поверх страницы (или «↗ во весь экран»).

**Просмотр.** Сцена играет петлёй `ELEMENT.len`; мышь — орбита, колесо — ближе, правая кнопка / Shift — сдвиг, двойной клик — камера сценария.
Свободная камера подменяет сценарную после `update` мира.

**Редактор (✋ Двигать, клавиша M).**
- Объекты — `w.items` движка: всё, что создано `card / box / lamp / model / hogCard / spriteCard` (+ `w.add(obj, pos, name)`, + `plane` с `name`).
  Без `name` в коде объект получает имя по порядку создания («карточка 40») — такие показаны курсивом в свёрнутом «без имени».
- Выбор: клик в кадре (прозрачные края карточек не ловятся) или в списке; Ctrl+клик — несколько. Рамка и подпись рисуются 2D поверх кадра.
- Движение: мышью по полу (плоскость через точку захвата), Shift — высота; стрелки — по полу относительно камеры (Shift ×5, Alt ×0.2),
  PageUp/Down — высота, Q/E — поворот 15° (Shift 5°), +/− — размер ×1.1, H — скрыть, Delete — вернуть как в коде, Esc — снять выбор.
  Несколько выбранных двигаются вместе.
- «В пределах разумного»: сдвиг ±12 м по полу, высота −2…+6 м, размер ×0.25…×4.
- **Группы.** Автоматические: безымянные объекты, созданные **подряд** и стоящие **на одном месте** (центр следующего внутри рамки группы по x/z),
  — ель из двух скрещённых карточек, опора с перекладиной и плечами, столб с лампой. Имя — по `key` карточки («spruce 12») или «группа 3».
  Свои: «🔗 Сгруппировать» (Ctrl+G) с именем; «⛓ Разгруппировать» (Ctrl+Shift+G) — и для автогрупп (запоминается `null`).
  Клик по части берёт группу, Alt+клик — часть; у части — «↑ Вся группа», «✂ Вынуть». Группа двигается целиком, поворачивается и масштабируется
  **вокруг центра своих частей**; у частей остаются их собственные сдвиги.
- «💾 Сохранить» → `POST /api/layout3d` → задача `layout3d` (без Claude, ~2–30 с): новая версия = тот же `element.js` + блок в конце,
  кадры переснимаются, в `renders[]` пишутся `layout`, `groups`, `feedback: «✋ расстановка: …»`. «↺ Всё как было» — к состоянию при открытии.

**Как это устроено в движке** (`stage3d.js`, шапка):
```js
// ==== расстановка автора (🧊 «✋ Двигать» в Штурме): …
{
  const w = typeof WORLD !== 'undefined' ? WORLD : X3.worlds[0];
  w.groups = { "Ели у таблички": ["карточка 2", "карточка 3", "карточка 722"], "группа 1": null };
  w.layout = { "ёжик": {"p": [-0.6, 0, -0.03], "r": -0.26, "s": 1.21}, "Ели у таблички": {"r": 0.26} };
}
```
`regroup()` строит группы после `build`. `draw()`: `_lay(false)` восстанавливает объекты из стека → `update` и тики сцены → `_lay(true)` кладёт
сначала сдвиги объектов, потом групп (с сохранением состояния в стек). Поэтому анимации сцены не ломаются, а расстановка переживает любой кадр.
Автоматические имена устойчивы, пока не меняется порядок создания объектов; поэтому «Поправить» от такой версии просит Claude сохранить блок
и закрепить автоматические имена через `name` (или собрать части автогруппы в `THREE.Group` с её именем).

## 6а. Редактор сцены «🎬 Оформить сцену» (S1 Claude Studio)

ТЗ и состояние — [studio/stage1-editor.md](studio/stage1-editor.md), формат — [studio/architecture.md §3.3–3.5](studio/architecture.md).
- **Старый формат** (`element.js` + блок расстановки) → кнопка «🎬 Перевести в редактор» в карточке 3D-сцены (задача `sceneconvert`, Opus, 5–10 мин):
  Claude пишет `render/<plan>/<el>/work/prefabs.js` + `scene.json`, сам сравнивает кадры «было / стало» (`scene_diff.py`), сервер проверяет ещё раз
  и пишет `e.stage = {work, from, fromV, diff, compare, ts}`. У сцены в редакторе «✋ Расставить» скрыт: расстановка теперь в редакторе.
- **Редактор** — `#/p/<plan>/pre/<el>/stage`: iframe `/tpl/editor.html?key=…&el=…` поверх страницы (модули `web/editor/`, движок `engine/scene.js`).
  Правки — операциями `POST /api/scene/op` (история `work/history.jsonl`, отмена — обратная пачка), `authored` — что автор правил руками.
- **Версия** («💾 версия», Ctrl+S) → `v<N>/` = `scene.json` + `prefabs.js` + кадры, запись в `renders[]` с `stage: true` — карточка показывает её как обычную версию.
  «🎞 клип» → `work/clip.mp4` (`render_clip.js`, звуки дорожки сведены), ссылка в `e.stage.clip`.
- **«Поправить»** у сцены в редакторе уходит не в `element_spec`, а агенту сцены (`sceneagent`, Opus): пины и «в целом» → одна пачка операций → новая версия.
- **Агент** в редакторе («/»): просьба → `sceneagent` (Sonnet, переключатель Opus) → одна пачка; лента — `e.stage.chat`. Пока он работает, сцена только для просмотра.
- CLI: `python studio.py scene show|ops|history|undo|version|clip|validate|finish <plan> <el>` (`finish` — зарегистрировать перевод, сделанный руками).

## 7. Сцены и их состав

- «Что в сцене» (`uses`) + @-упоминания в текстах сцены = состав (`cast_of`), с пометкой, откуда элемент попал.
- При рисовании сцены Claude получает черновик, код и ассеты каждого из состава и **ставит их, а не рисует заново**
  (2D — вызовом их `drawX`, 3D — карточкой `w.card({draw: drawX…})` или `w.model` из ассета).
- Предупреждение перед рисованием, если у кого-то из состава нет черновика.
- В экспорте у сцены — таблица «Что в сцене» со ссылками на папки; у персонажа/пропса — «Стоит в сценах».

## 8. Бесплатные ассеты 📦

Карточка под референсами элемента (кроме звуков). Модуль `ideas/assets.py` (CLI `search` / `fetch`), ключи не нужны.

| вид | источники | что качается «в работу» |
|---|---|---|
| 🧊 3D | **Poly Pizza** (low-poly, много CC0 от Kenney и Quaternius, CC-BY от Google Poly) · Poly Haven (CC0) · Sketchfab (скачиваемые) · OpenGameArt (3D) | `.glb` / glTF 1k с текстурами; Sketchfab — только с токеном `.studio/sketchfab_token.txt`; OGA — файлы страницы (часто не glTF → только референс) |
| 🖼 2D | Openverse (фото и рисунки под CC: Flickr, Wikimedia…) · Wikimedia Commons · OpenGameArt (2D) | картинка (если оригинал не отдаётся — превью) |
| 🧱 текстуры | ambientCG (CC0) · Poly Haven (CC0) | карты 1K (цвет, нормали, шероховатость…), главная — карта цвета |

- **Строка результата:** `{src, id, title, kind, thumb, page, license, attr (нужна подпись), author, fmt, dl (можно скачать), note}`.
- **📌 В реф.** — превью (в PNG) уходит в `refs[]` элемента с подписью «название — источник · лицензия · автор».
- **⬇ В работу** — задача `assetfetch`: файлы в `_ideas/files/<plan>/assets/<id>/`, запись в `assets[]`
  `{id, src, sid, title, kind, fmt, license, attr, author, page, dir, main, files, size, preview, note, why}`; `why` — «что взять», можно с @.
- **🧊** — покрутить модель: `/tpl/stand3d.html?model=<url>&view=1` (пол, свет, камера облетает; Poly Pizza грузится прямо с их CDN).
- **✨ Подобрать** (`assets`, Sonnet, medium, ~20–60 с): Claude ищет командой `python assets.py search "q1" "q2" --kind …`
  (только она разрешена; несколько запросов в одной команде), учитывает описание, референсы, «Что нужно», состав сцены и уже взятое,
  возвращает 3–6 находок с `why` и `use` (work — брать как есть, ref — только образец). Сервер находит их тем же поиском заново
  (превью и лицензия — из каталога, не со слов Claude) и кладёт в `picks[]`. **Ничего не скачивается без автора.**
- **Использование:** в черновике — через `MODELS` + `w.model(key, { h, pos, rotY, name, matte: true, anim })` (модель встаёт на пол по центру,
  `matte` — матовый «бумажный» вид), картинки — `PICS` / `spriteCard` / вырезки, текстуры — в `draw` плоскости.
  Загрузчик — `engine/vendor/GLTFLoader.js` + `SkeletonUtils.js` (three r186 examples, MIT), `boot3d.js` грузит их необязательно.
- **Права:** лицензия и автор едут в README элемента; где `attr` — пометка «нужна подпись автора», реализатор переносит в «Права» упаковки.

## 9. Звуки 🔊

- **Кандидаты** `sounds[]` `{id, file, title, src, license, author, page, url, dur, peak_t, rms_db, start, end, by, why}` — wav в `files/<plan>/sfx/`.
  - «✨ Подобрать звук» (`sound`, Sonnet, medium): Claude ищет `python sounds.py search` (библиотека пайплайна, Freesound, Commons) и в интернете,
    сервер скачивает 3–5 кандидатов. Учитывает «Какой нужен / что не так» (`ask`) и заметку о сведении.
  - «🔎 Искать» — то же без Claude, с прослушиванием; «⬇ Взять».
  - «⬇ По ссылке» — любая страница со звуком, прямой файл, Freesound/Commons, **YouTube и видеосайты через yt-dlp**; «с / по» — вырезать кусок.
    Длинное режется до 180 с, большие файлы и куски тянутся потоком ffmpeg.
- **Микс** `mix[]` `{id, sid, at, gain, note}` + `mixNote`: ✓ у кандидата добавляет слой; сдвиг (с), громкость (%), порядок, пояснение «что это и куда».
  «▶ Слушать вместе» играет слои в браузере так же, как `audio.py` сводит `file:`-звуки (нормировка по пику × громкость).
- **Экспорт:** `assets/sfx/<slug>.wav` — готовый (один слой — копия, несколько — `preprod.premix`), слои — `assets/sfx/<slug>/<n>-….wav`,
  в README — таблица слоёв, готовые строки `add(t, 'file:…', gain)` и источники с лицензиями.

## 13. Дальше: редактор оформления сцены

> **Итоговый план — в [studio/](studio/README.md)** (архитектура, этапы, ТЗ этапа 1). Ниже — первоначальный набросок и протокол вопросов к автору; где они расходятся, прав `studio/`.

Решения автора (30.09.2026):
- Редактор — **этап препродакшена**: «оформить сцену» — часть карточки сцены, не отдельный инструмент и не часть ревью ролика.
- Приоритет: (1) двигать объекты в сцене, (2) редактор камеры, (3) редактор движения объектов и персонажей, (4) включать нужные анимации персонажа,
  (5) добавлять анимации персонажу **промптом** — они сохраняются у персонажа и переиспользуются в других сценах,
  (6) слегка править позу персонажа «по-умному» (растянуть руку и т. п.) с подписью для Claude.
- Персонажи пока **2D-карточки в 3D-пространстве** (как в Paper Mario). Заложить, но не делать: 3D-персонажи с их анимациями.
- Редактор в ревью собранного ролика не нужен (данные сцены при этом должны его допускать). Sketchfab-токен пока не нужен.

Прожарка, раунд 1 (30.09.2026):
- Сцена в препродакшене — **репетиция движений**, при сборке её растягивают под голос (а иногда голос под неё). Ходьба по пути — автоматически, с возможностью перебить. Длина сцены — любая, по потребности.
- Ставка на **3D + 2D**, в перспективе ролики целиком в 3D; чистая 2D-аппликация — пройденный эксперимент.
- **Несколько каналов:** редактор масштабируется на разные проекты-каналы («Доедать будешь» с ёжиком, канал про WoW с троллем…) — у каждого своя библиотека.
- **Скелеты:** новому персонажу Claude сам прикидывает скелет (похож на ёжика — скелет ёжика, монстр — свой), автор может его поправить; персонаж со скелетом попадает в библиотеку и переиспользуется в других сценах и роликах.
- **Анимации:** автор пишет эмоцию или действие → Claude учит персонажа → дальше автор использует её сам, без Claude.
- Ручные правки автора (камера, расстановка) Claude не трогает, если об этом прямо не попросили.
- Одна сцена может быть целым роликом с несколькими планами камеры (комната в ностальгическом ролике); результат — полная раскадровка, по которой Claude собирает ролик без догадок.
- Утверждается **вся петля сцены**. При сборке ролика сцену можно поменять, и в правках ревью тоже нужно двигать персонажа и объекты (хотя бы как пометку для Claude).
- Звуки на шкале сцены; если звука нет — Claude подставит сам.
- **Стандартные хоткеи** видео- и 3D-редакторов. 3D-ассеты, которые делает Claude, — тоже в библиотеку. Всё, что происходит в редакторе, должно быть понятно ИИ-агенту: это видеоредактор, совмещённый с агентом.

Прожарка, раунд 2 (30.09.2026):
- **Движок остаётся** (three.js в браузере: один движок у редактора, черновиков, ревью и рендера). Визуал редактора — отдельный, «профессиональный», как у Blender / Premiere.

### 13.1 Сцена как данные

Сейчас сцена — код Claude, а ручные правки — заплатка по именам поверх него. Для камеры, ключей и поз это не годится:
код нельзя одновременно править руками и Claude. Поэтому вводим `scene.json` рядом с `element.js` в папке версии.

```
element.js  (код, пишет Claude)                          scene.json  (данные; правят и редактор, и Claude)
  PREFABS = { trailSign(g, cw, ch, T, o), spruce, … }      { len: 6, fx: 'dusk', fog: [...], lights: [{ type: 'sun' | 'lamp', … }],
  функции build… для сложных предметов                        camera: { keys: [{ t, pos, target, fov, ease }] },
  ANIMS у персонажей — см. 13.4                               objects: [{ id, name, prefab | model | el, pos, rotY, scale, hide,
                                                                  group, keys: [{ t, pos, rotY, scale, ease }],
                                                                  clips: [{ t, anim, dur, loop, speed }], pose: [{ t, params, note }] }] }
```
- **Префабы** (код) — как предмет выглядит; **scene.json** — что где стоит, когда движется, как снята камера, какие анимации включены.
- Стенд строит мир из `scene.json` + `PREFABS`; редактор меняет только `scene.json` и сохраняет версию **без Claude**;
  Claude при «Поправить» меняет и то, и другое. Имена и группы становятся родными (автоимена не нужны).
- В ролик едут оба файла: `buildFromScene(w, scene, PREFABS)` в `stage3d.js` шаблона.
- Нынешний блок `w.groups / w.layout` конвертируется в `scene.json` автоматически; старые черновики открываются в новом формате.
- Такая сцена при желании подключается к ревью ролика позже — для этого достаточно, чтобы ревью умело открыть тот же `scene.json`.

### 13.2 Экран «Оформление сцены»

Кнопка «🎬 Оформить сцену» в карточке сцены открывает редактор на весь экран (внутри препродакшена, `#/p/<id>/pre/<el>/stage`, Esc — назад).
```
┌ объекты (дерево, группы) ┬──────────── кадр 9:16 (безопасные зоны, рамка камеры) ────────┬ инспектор ┐
│ 🔗 Ели · 5   ▸           │                                                                │ имя, позиция, поворот, размер (числа)
│ ёжик  ● ключи            │            3D-вид (орбита) | «глазами камеры» (F)              │ персонаж: анимации, поза
│ Табличка                 │                                                                │ ассеты / состав
├──────────────────────────┴────────────────────────────────────────────────────────────────┴───────────┤
│ таймлайн: ▶ ⏸ 0:02.4 │ 🎥 камера ◆──◆────◆ │ ёжик ◆───◆ │ ▭ идёт ▭ машет │ Дэнни ◆ │ метки звука │
└──────────────────────────────────────────────────────────────────────────────────────────────────────┘
```
Общее: undo/redo, точные числа в инспекторе, дублировать / удалить / переименовать, клавиатура везде (как и сейчас: стрелки, Tab по спискам).

### 13.3 Камера и движение объектов

- **Камера.** Дорожка ключей на таймлайне; «🎥 ключ с этого вида» берёт текущий вид свободной камеры, ключ можно двигать в кадре (рамка камеры,
  линия пути), сглаживание (ease) на каждом отрезке, ручная дрожь (`handheld`), fov, фокус для глубины резкости. Предпросмотр «глазами камеры» 9:16
  с зоной субтитров (y 1400–1540) и краями. Итог — `camera.keys` = то, что сейчас делает `w.camKeys`.
- **Объекты.** Двигаешь объект при остановленном курсоре времени — создаётся или обновляется ключ; путь виден линией в кадре; сглаживание;
  готовые движения из `moves3d.js` (прыжок, вылет, бумажный переворот, походка по пути) как пресеты-клипы. Группы двигаются целиком.

### 13.4 Анимации персонажа

Два слоя, оба — общая библиотека персонажа и работают одинаково для любого героя:
1. **Движение карточки** (переезд, прыжок, переворот, шаг) — ключи и пресеты из 13.3.
2. **Анимация позы** — функция времени, которая возвращает параметры рисования (`drawHog`: `armL/armR`, `lenL/lenR`, `look`, `mouth`, `walk`, `backView`, `prop`…).

У элемента-персонажа появляется `anims[]`: `{id, name, desc, kind: 'pose' | 'move', dur, loop, fn, prompt, strip (PNG кадров), by, ts}`, код лежит в его `anims.js`
(в экспорте — `refs/препродакшен/char/<slug>/anims.js` и таблица в README). Все анимации персонажа доступны в любой сцене.

- **Включить:** на таймлайне у персонажа полоса клипа `{t, anim, dur, loop, speed}` из выпадающего списка (Tab/Enter, как везде).
- **Добавить промптом:** в «Правках» персонажа поле «+ анимация» («чешет затылок левой лапой, 1.5 с», «испуганно оглядывается»). Кнопка `anim` (Claude, Opus):
  пишет функцию позы в `anims.js`, рисует ленту кадров, смотрит, правит, кладёт в `anims[]` с превью. Дальше её можно включать в любой сцене.
  Удачные общие движения — в `engine/moves3d.js` и `_studio/ANIMATIONS.md`.
- **Слой под будущее:** у записи есть `rig: 'card2d'`. Для 3D-персонажей (`rig: 'glb'`) клипами станут анимации из самого glTF (`w.model(..., {anim})` это уже умеет) —
  на таймлайне они работают точно так же.

### 13.5 Поза «по-умному»

Цель: слегка поменять позу героя в конкретном кадре — вытянуть руку к кнопке, отвести за спину, повернуть голову — и чтобы Claude собрал это красиво.
1. **Ручки.** Выбрал персонажа — в кадре появляются ручки на лапах и голове. Тянешь лапу: редактор сам считает угол и длину (`armL/lenL` …) и показывает результат сразу
   (без Claude). Для `hogCard` это работает на всём, что умеет `drawHog`.
2. **Подпись для Claude.** Если параметрами не выразить: ставишь пин на часть тела, стрелку к цели и пишешь, что имеется в виду
   («тянется к кнопке лифта, пальцы на ней», «прячет папку за спину»). Правка сохраняется как `pose[]` на этом времени: `{t, params, note, frame}` — кадр с отметками и текущие параметры.
3. **Регенерация.** При «Поправить» Claude получает кадр с пометками, параметры и текст, пересобирает позу так, чтобы попасть в цель, и при желании сохраняет её в библиотеку
   персонажа как именованную позу или клип (переиспользуется).

## 14. Открытые вопросы

1. Персонаж, который «идёт по пути» (карточка едет, а поза шагает): привязывать ходьбу к скорости движения автоматически (`gait3`) или ставить клип руками?

## 🎬 «Для финала» в работе (с редактором сцен)
Пункты «для финала» — ТЗ автора к готовой сцене / ассету. Теперь они не только уходят в экспорт и в промпт черновика, а становятся задачами:
- `scene brief` печатает открытые пункты сцены и её состава (персонажи, пропсы) с id — агент видит их в любой просьбе по сцене, «✨ Собрать» делает их до монтажа;
- у сцены в редакторе — «✨ Сделать в сцене (N)»: агент (Opus) делает пункты в сцене, проверяет кадрами и закрывает `scene final-done PLAN EL ID,… "что сделано"`
  (`elements[].final[].done` + `reply`; в карточке — ✓ и зачёркнуто, ↺ — вернуть в работу; ✓ можно поставить и руками);
- у пропса / персонажа — «→ в правку черновика»: открытые пункты становятся пунктами правки, «Поправить» делает новую версию.

**✓ Утвердить все** — в шапке каждой категории (персонажи, пропсы, сцены, звуки), если там есть неутверждённые: все предложенные → ✓ (вычеркнутые ✗ не трогает); перед этим — сколько и сколько из них без черновика / выбранного звука.
