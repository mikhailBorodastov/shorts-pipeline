# Пайплайн вертикальных шортов (инструкция для Claude)

Рабочая папка (родитель `_pipeline/`, например `D:\work\Animations`) содержит проекты шортов — по одному в подпапке. Движок и шаблон лежат в `_pipeline/` (документация для пользователя — `_pipeline/README.md`). В корне рабочей папки лежит `CLAUDE.md` с одной строкой `@_pipeline/CLAUDE.md`, так что эта инструкция подключается в любой сессии, открытой там.
Если в рабочей папке есть `chrono trigger/`, это первый проект (птички, сделан до шаблона) — образец богатых сцен: `chrono trigger/src/scenes.js`.

Пользователь пишет по-русски, отвечай по-русски. Стиль по умолчанию: **бумажная аппликация** (коллаж). Фигуры вырезаны из бумаги, у них рваная кромка, зерно и тени; фото и логотипы вклеены вырезками с белой обводкой; надписи на тетрадных листках и от руки (шрифт Caveat); фон всё время слегка движется. Герой — **наш бумажный ёжик**, серый, из сотен рваных полосок, с тёмной маской, большими глазами и светлой мордочкой (в духе «Ёжика в тумане»). Он был во всех роликах начиная с PS6. **Не бери круглого ёжика в духе Смешариков из `src/chars.js`**: это старый стиль. Готовый код (набор `torn/cut/note/photo/sticker/label/scrawl` + `drawHog(ctx, x, yНог, рост, {kind: 'adult'|'kid'|'friend', look, lid, mouth, armL/armR, lenL/lenR, hoodie, cap, glasses, phones, beard, badge, wink, tired, prop})` + `aim()` для наведения лапы) копируй из последнего проекта: `ИИ пузырь/src/scenes.js` (там же гипно-волны, стикеры-цифры и переход `pop` в `main.js`). Палитру и фон подбирай под историю: серый туман (PS6), клетчатая тетрадь и крафт (ИИ пузырь), нуар и т.д.

## 3D-сцены (stage3d.js): Paper Mario + Octopath
В шаблоне есть 3D-слой `src/stage3d.js` (three.js r186 + postprocessing 6.39 + Reflector в `src/vendor`, грузит `vendor/boot3d.js`). Мир `world3d({ fx, build(w), update(w, lt, D, T) })` рендерится в общий WebGL-холст и вклеивается в 2D-кадр: `SCENES[k].draw = (ctx, lt, D, T) => { WORLD.draw(ctx, lt, D, T); /* 2D поверх */ }`. Субтитры, плашки, переходы, sfx не меняются. API и грабли описаны в шапке `stage3d.js`, образец целого ролика — `Коты сыщики 3D/src/yard3d.js` (двор-диорама, время суток, catCard) и `shots.js` (сцены, склейки мини-локаций внутри секции, THUMBNAILS с 3D-кадрами).
- **Анимации копим, а не планируем:** движения ёжика и эффекты придумываем под конкретный ролик, а удачное сразу обобщаем в `template/src/moves3d.js` (или `hogCard`/`drawHog`) и записываем строкой в `_pipeline/ANIMATIONS.md` (что делает, где впервые, как вызвать). Перед тем как писать новое движение — загляни в каталог.
- **План доработок и история правок** — `_pipeline/HANDOFF_3d.md`. Пиксельный ёжик (`pixelHogCard`) пользователю не зашёл — не использовать, пока сам не попросит.
- **Когда брать:** если пользователь просит 3D, «как Paper Mario / Octopath», диораму. По умолчанию стиль по-прежнему 2D-аппликация.
- **Герои:** `hogCard` (бумажный ёжик: `c.hog = { walk: gait3(...), fedora, mouth, look, arm… }`, лапки уже есть; нужен тулкит с `drawHog` — копируй файл `Не жми эту кнопку в лифте детской поликлиники/src/paper.js` (подключается перед stage3d.js; `drawHog` умеет `walk` и `backView` — спина из иголок для `turnHog3`), `pixelHogCard` (HD-2D), `spriteCard` (фото/спрайт с кромкой, `c.pt(fx, fy)` для прицепа шапок и глоу). Движения: `popUp3`, `flip3` (бумажный переворот — поворот спиной, смена карточки), `hop3`, `gait3`.
- **Фидбек пользователя:** каждой смене мысли — своя локация, а не один сет на весь ролик. Перечисления («в кусты, в подвал, под машину») — отдельными мини-сценами с жёсткими склейками. В 9:16 всё должно влезать по ширине (группы — сеткой, камера сверху). Монстров/существ старыми гравюрами не делать — просить референсы или искать цветные игровые спрайты. Нравится: pop-up телефон, окна с котами, отражение в 3D-зеркале.
- **Кадр подольше:** `[пауза 1.5]` прямо в строке VO (tts.py вставит тишину после слова, интонация не рвётся), а не отдельная секция.
- **Имена и расстановка автора:** у объектов мира (`card`, `box`, `lamp`, `model`, `hogCard`, `spriteCard`, `w.add(группа, pos, 'Имя')`) есть `name` → `w.items`; `мир.layout = { 'Имя': { p: [dx, dy, dz], r, s, hide } }` двигает их поверх кода после `update()`. Группы (`мир.groups = { 'Ели слева': ['карточка 3', …] }`, собираются в `regroup()` после build) двигаются, крутятся вокруг своего центра и масштабируются целиком; безымянные объекты, созданные подряд на одном месте (ель из двух карточек, опора с перекладиной), группируются сами — «spruce 12» по `key` карточки или «группа 3». Такой блок приходит из препродакшена («✋ Расставить» в Штурме) в конце `element.js` — переноси его вместе с миром и не меняй `name` объектов.
- **glTF-модели:** `ASSETS.models = { key: '../assets/models/x.glb' }` грузит `stage3dInit` (загрузчик — `vendor/GLTFLoader.js`, three r186, MIT), в мире — `w.model(key, { h, pos, rotY, name, matte: true, anim })`: модель встаёт на пол по центру, `matte` делает её матовой, «бумажной». Берутся из препродакшена (📦 ассеты) — лицензии в README элемента.
- **Проверка:** `render.js snap` как обычно. `RENDER_PAGE=demo.html` рендерит другую страницу проекта. Ошибки WebGL видны в консоли snap (`[pageerror]`).
- **Грабли:** в шейдерах не использовать `pow(0.0, y)` (NaN на D3D → bloom заливает кадр чёрным); спрайты прятать `visible = false`, а не масштабом 0. `WT(i, 'кот')` находит первое слово с подстрокой («котов»!) — бери уникальные куски. Кадры клипов в `assets/*/f%03d.jpg` бывают 480×360, а не 320×240 — считай кроп по реальному размеру.

## Игровой формат (пародия на хоррор-игру) — впервые в «Не жми эту кнопку»
Нарратор только в хуке (секция с VO), дальше сцены-паузы из script.md (таймкод + «Картинка» + «Текст» без VO). Образец — `Не жми эту кнопку в лифте детской поликлиники/src/scenes.js`:
- `DIALOG` — субтитры в стиле Silent Hill: шрифт пользователя `PostironicHillSilentHill1Font` (`assets/fonts/SilentHill1.ttf`, без «ё»; кегль ~88 — у шрифта мелкие буквы), жёсткая тень, между репликами паузы «как в игре», мигающий треугольник «дальше», если следом реплика или меню; `talk: 'mom'|'hog'` = реплика вслух «звериной речью», без `talk` — мысль. `MENUS` — игровые меню с курсором и выбором. `dialogSfx(add, ta, tb)` ставит звуки речи и меню, `drawDialog(ctx, T)` рисует.
- **«Звериная речь» как в Animal Crossing:** `_pipeline/animalese.py` — по слогам «согласная + её гласная» («ка-же-ца»), не по буквам: буквенная версия («ка-а-жа-е…») звучала как «не то говорит». Слоги озвучены edge-tts один раз, кэш `_pipeline/animalese_cache/` (`python _pipeline/animalese.py --cache` — все ~240 слогов на голос). Звук `talk:<who>:<текст>` рендерит отдельная дорожка в `audio.py` (`TALK` — пресеты голосов), музыка приглушается под неё как под голос. Для голоса текст переписывается как слышится (`PHON`: «кажется» → «кажеца»), субтитры остаются обычными.
- **Конструктор голоса** для пользователя: `src/animalese.html` (в шаблоне; буквы — скопируй `_pipeline/animalese_cache/*` в `assets/animalese/`). Тот же алгоритм и RNG, что в `animalese.py`; «Скопировать настройки» даёт JSON — вставь его в `TALK` в `audio.py`.
- Свои звуки из файлов: `add(t, 'file:assets/<файл>.wav', gain)`.

## Процесс

### Старт: с чем пришёл пользователь — три входа
1. **Есть идея, инфоповод или материалы** → шаг 0, как раньше. Упаковку продумывай заранее: на викторине предложи одну связку «хук + название + обложка» (другие — только если попросит) (подробно — в сценаристе, этап 2).
   Если идея есть, но её надо доработать до сценария (биты, название, **препродакшен** — сцены, персонажи, пропсы, звуки), предложи путь «Есть идея» в `Штурм идей.bat` (раздел ниже): там Claude задаёт вопросы, пользователь накидывает референсы, черновики элементов и звуки готовятся до сценария.
2. **Идеи нет** («давай штурманём», «что снимем?», «помоги выбрать тему») → **Штурм идей** (раздел ниже). Предложи открыть `Штурм идей.bat` в рабочей папке и штурмовать там самому с кнопками ✨ — или веди штурм в чате и записывай его через CLI сервиса, чтобы пользователь видел всё на странице. Формат выбирается сразу: ⚡ шортс или 🎬 длинное видео на 8–15 минут.
3. **Пришёл со штурмом** («сценарий по штурму в папке X», «делаем штурм <id>») → прочитай `X/refs/штурм.md` (или `_ideas/plans/<id>.md`; обзор всех штурмов — `_ideas/index.md`). Там выбранная идея, биты «вопрос → ответ» с источниками, 7 ответов (или вопросы Claude и ответы автора — это его решения), смыслы и образы, связка «название + обложка (+ хук и первый кадр у шортса)», структура по слотам, эскизы и разбор видео-референсов — в `refs/штурм/`, **препродакшен** — в `refs/препродакшен/` и `assets/sfx/`. Дальше шаг 0 по сценаристу, но короче:
   - этап 1 — сверить биты с источниками (всё с пометкой «проверить» — проверить);
   - викторина — только то, что штурм не решил (тон, финал, реальные материалы, обложки или ёжик-пародии);
   - хук и название — из связки, порядок сцен — из структуры штурма (или из битов, если штурм по пути «Есть идея»). В шаге E выбранная связка — основа упаковки.
   - Сцены сценария строй из локаций препродакшена, а «Картинку» пиши его элементами (названия как в `штурм.md`).

### 0. «Напиши сценарий» / дали материалы или инфоповод без готового сценария
Работай строго по `_pipeline/prompts/scriptwriter.md`, три этапа без перескоков: **изучить материалы → викторина (AskUserQuestion, 3–5 вопросов, до двух раундов) → сценарий**. Там же правила удержания, меню структур и границы (факты только из источников, атрибуция, дети, насилие, чужие кадры) — они обязательны.
**Подача — по `_pipeline/prompts/style-guide.md`** (пользователю так нравится гораздо больше): темп ~2,65 слова/с, фраза ~10 слов, хук из пяти типов гайда, «Но» в начале фраз, цифры с бытовым сравнением, сухая кода, которая перекликается с хуком, без CTA и без морали. Для техно-новостей основная схема — В («новость → что все пропустили → абсурд последствий»).
Адаптация под пайплайн:
- Сначала создай проект (`python _pipeline/new_project.py "<название>"`) и скопируй материалы в `refs/` (видео и фото как есть; длинные видео смотри контактными листами).
- Сценарий пиши **сразу в `<проект>/script.md` в формате сценариста** (`### 0:00–0:04 — НАЗВАНИЕ`, `**Картинка:**`, `**Текст:**`, `**VO:**` + строки `> …`). `tts.py` читает этот формат напрямую: каждая сцена с VO — отдельная секция; сцена с таймкодом и картинкой, но без VO — пауза этой длины (тишина как приём, но не перед финалом); упаковка, источники и прочие разделы без VO игнорируются. Копию сохрани в папку с материалами, как просит промпт.
- В шапку `script.md` (до первой сцены) добавь служебные строки: `voice:`, `rate:` (цель ≈ 2,65 слова/с — обычно `+25%…+30%`), `произношение: как пишется = как читать` для имён, аббревиатур и латиницы, `вопрос: слово` для слов с вопросительной интонацией.
- На викторине про визуальный стиль: по умолчанию наш стиль (бумажная аппликация + бумажный ёжик); предлагай палитру и настроение под историю (например, нуар-палитра для тру-крайма, как в «Джигане»), а не смену движка.
- Если есть главный видео-референс (трейлер, запись), добавь в шапку `видео: refs/<файл>` и в каждую сцену поле `**Кадры …:**` с таймкодами (`08:24.0–08:32.0`, `стоп 09:49.5`; другой файл — `[имя.mp4]` в том же поле). По ним раскадровка покажет кадры.
- Перед показом прогони `python check_script.py` в папке проекта (измеримые пункты гайда: длина, темп, длина фраз, первая фраза, числа, «Но», добивки, обращения, CTA, тишина перед финалом). Исправь всё, что ❌, пройди ручные пункты чек-листа (гайд, п.8) и коротко покажи пользователю итог. После `tts.py` скрипт берёт реальные тайминги голоса, прогони его ещё раз.
- Запусти сервер ревью (шаг A.5) и дай ссылку на **раскадровку** `http://localhost:<порт>/src/script.html` (или скажи запустить `script.bat`). Там пользователь правит текст сцен, слушает голос по сценам и оставляет заметки: фактчек, переписать, картинка. Сразу прогони `python tts.py`, чтобы в раскадровке были реальные тайминги и голос.
- После сценария покажи концепцию и спроси, собирать ли анимацию. Дальше — шаг A с пункта 2.


### A. «Сделай шорт по сценарию в папке X»
1. Если папки нет — `python _pipeline/new_project.py "X"`. Если пользователь прислал сценарий в чат, запиши его в `X/script.md` в формате шаблона (секции `## `, поля `Визуал:` и `Голос:`).
2. Прочитай `script.md` и всё в `refs/`. **Если есть `refs/штурм.md`, это часть ТЗ на всех этапах, а не только на сценарии.** Смотри и эскизы в `refs/штурм/*.png`.
   - **Смыслы в образы** — ТЗ на визуал и ассеты: какие логотипы, спрайты и кадры искать, что вклеивать вырезками. Смыслы «без этого никак» обязаны появиться в кадре.
   - **Первый кадр и хук связки** — это сцена 1 ролика.
   - **Концепт обложки** (тип по карте, текст, эскиз) — первый вариант в THUMBNAILS.
   - **Структура штурма и заметки к слотам** — порядок и смысл сцен.
   - **Жанр** (новость, история, сюжет) задаёт тон анимации.
   - **Вырезанные биты** — запас на замены при правках.
   - **Препродакшен** — начни с `refs/препродакшен/README.md` (как пользоваться + указатель всех элементов), всё машиночитаемо — `manifest.json`. У каждого элемента папка `refs/препродакшен/<char|prop|scene|sound>/<slug>/` с **`README.md` — это ТЗ элемента, читай его перед тем, как делать элемент**: что это, где в ролике, **«Для финала»** (прямые требования автора к готовому ассету, пины — на `final_pins.png`; выполни каждый пункт), состав сцены (`cast`: «Что в сцене» + отмеченные через @), где элемент стоит, файлы.
     - Черновики — не финал, а согласованный образ и стартовый код: `vN.png` + `element.js` (2D — функция `drawX(...)`, переноси в `scenes.js`; 3D — мир `world3d`, переноси в `src/<проект>3d.js`). Код написан на тулките `refs/препродакшен/_toolkit/paper.js` — подключи его как `src/paper.js` перед `scenes.js`. ✓ — утверждён автором, «предложен» — не проверен.
     - Сцену собирай из её `cast`: код персонажей и пропсов бери из их папок (там последняя версия), а не из копий в коде сцены.
     - **Расстановка автора** (3D): если в конце `element.js` есть блок `// ==== расстановка автора` (`WORLD.layout = {…}`), автор сам двигал объекты сцены — перенеси блок вместе с миром (`мир.layout = …`) или впиши сдвиги в координаты; `name` объектов не меняй.
     - **📦 Ассеты** — бесплатные модели, картинки и текстуры, которые автор нашёл и взял «в работу»: уже лежат в `assets/models/<slug>/` и `assets/img/<slug>/`, в README элемента — источник, лицензия и готовые строки `ASSETS.models` / `ASSETS.images`. Используй их; где лицензия требует подписи (CC-BY), автор идёт в «Права» упаковки.
     - Звук: `assets/sfx/<slug>.wav` — готовый (если слоёв несколько — уже сведён), слои — `assets/sfx/<slug>/<n>-….wav` со сдвигом, громкостью и пояснением «что куда» в README; там же готовые строки `add(...)` и источники с лицензиями (перенеси в «Права» при упаковке).
     - `@[Название]` в любом тексте штурма — ссылка на элемент с таким названием (указатель — в README папки и в `штурм.md`).

   Если в сценарии пользователь что-то поменял, прав сценарий, но расхождения со штурмом назови.
   Длинные видео смотри контактными листами через ffmpeg (`fps=1/N,scale,tile`), вырезай нужные клипы в `assets/<name>/f%03d.jpg` (кроп 4:3, 320×240, 15 fps).
3. `python tts.py` → черновой голос и `src/vo_timing.js`. Сцена k = секция k. Если ролик сильно длиннее 60 с — подними `rate:` в шапке script.md, но не выше ~+35%.
4. Напиши `src/scenes.js`: по одному объекту сцены на секцию (API описан в шапке файла). Все события привязывай к словам через `WT(секция, 'слово')`, звуки задавай через `sfx(add)`, ассеты объявляй в `ASSETS`.
   **Звуки** бери из библиотеки: каталог `_pipeline/sfx_library/index.md` (id · длина · момент пика · громкость), поиск `python _pipeline/sfx_library.py find <слово>`. Вызов: `add(t, 'lib:<id>', gain, 'peak')`; `'peak'` ставит самый громкий момент звука на `t` — для ударов, вжухов, взрывов. Кусок длинного звука (эмбиент, толпа, дождь): `'lib:<id>|<смещение>|<длина>'`. Вжух на всех переходах из библиотеки: `const TRANS_WHOOSH = 'lib:whoosh/15-quick-a'` в scenes.js. Райзеры и нарастания (`riser/*`, `other/buildup-*`) заканчиваются пиком: ставь их так, чтобы пик пришёлся на смену сцены. Короткие UI-звуки (`other/pop`, `other/click`, `glitch/*`) — на появление плашек. Стандартные имена (`pop`, `whoosh`, …) уже отображены на библиотеку в `LIB_DEFAULTS` в `audio.py`. Категорию `meme` (чужие записи) используй только если пользователь попросил. Не ставь больше 2–3 звуков на одну секунду. **Смотри длину звука в index.md**: всё длиннее ~3 с (эмбиенты, мем-треки вроде `other/cash-mre` на 20 с) ставь только срезом `|смещение|длина`, иначе звук протянется через полминуты ролика. Каждый звук по умолчанию плавно затухает в конце (`FADE` в `audio.py`: фейд начинается после пика, до 1.2 с; `FADE = None` — выключить). Если пак ещё не импортирован, скажи пользователю команду `python _pipeline/sfx_library.py import <папка>`.
5. Сервер ревью: `python review_server.py` в фоне (без `--open`, если пользователь уже смотрит страницу). Он сам берёт свободный порт из 8765–8784 и пишет его в `build/.review_port`; `python review_server.py port` покажет порт уже запущенного сервера этого проекта. Для `node render.js` задай `REVIEW_PORT=$(python review_server.py port)` (`build.sh` делает это сам). Давай пользователю ссылку с правильным портом. Не держи сервер проекта во встроенном браузере дольше, чем нужно: `preview_start` с фиксированным портом 8765 занимает порт, который ждёт `review.bat`.
6. Проверяй глазами: `node render.js snap 1.5,4,8.2,... build/snap.png` → Read. Ищи наложения (субтитры, плашки, персонажи), пустые кадры, края фона при движении камеры, переходы (снимай кадры внутри окна перехода).
7. `./build.sh` → `out/X.mp4`. Отправь файл через SendUserFile и дай ссылку на ревью `http://localhost:<порт>/src/review.html` (порт — из `python review_server.py port`), или скажи запустить `review.bat`: он сам откроет нужную страницу.

### B. «Глянь правки»
1. Прочитай `X/review/notes.md` и нужные `review/shots/N.png`. Пин на скрине = место, о котором речь. К правке могут быть приложены картинки-референсы (строка «Референсы: review/refs/N_k.png…» в notes.md): открой их через Read, это образец того, как должно быть.
2. Если правок много — сначала дай план (таблица «# → что делаю»), потом делай.
3. Правь `src/scenes.js`, `chars.js` и т.д. Открытая страница ревью перезагрузится сама на том же таймкоде.
4. Проверь через `render.js snap` на таймкодах правок.
   **Звуковые правки** (`🔊` в notes.md, поле `sfx` в notes.json) описывают конкретный звук: `cue #i`, `type`, время `t`, сцену. В `scenes.js` найди соответствующий `add(...)` в `sfx(add)` этой сцены (по типу и времени). Действия: **заменить** — поменяй тип на `lib:<id>` (с `'peak'`, если так указано); **громкость ±N dB** — умножь gain на 10^(N/20); **удалить** — убери вызов; **добавить** — новый `add(t, 'lib:<id>', gain, align)` в сцене, где стоит момент. Вжух перехода (`origin: transition`) создаёт движок: удаляется через `noWhoosh: true` на входящей сцене, заменяется так: `noWhoosh` плюс свой `add` в `sfx` этой сцены. После звуковых правок обязательно запусти `./build.sh audio`: дорожка звуков в ревью читает `build/sfx_resolved.json`.
5. На каждую правку ответь: `python review_server.py reply N "что сделано" --done`. **Никогда не перезаписывай `notes.json` целиком** (сервер сливает заметки по полю `updated`, а `reply` ставит его сам).
6. Если менялся текст или порядок секций — `python tts.py`. После этого или после изменения звуков — `./build.sh audio` (для звука в ревью), в конце `./build.sh` и отправь видео.

### C. «Подставь мою озвучку»
Файлы пользователя лежат в `build/vo/sec0.*`, `sec1.*`… → `python align.py` (faster-whisper, модель `small`; для скорости `WHISPER_MODEL=base`) → `./build.sh`.
Если запись пришла **одним файлом**: скопируй её в `refs/`, распознай целиком (faster-whisper, `word_timestamps=True`, `device='cpu'`), найди границы секций по словам и режь в самой тихой точке между ними (минимум RMS). Нарезай в `build/vo/secN.wav` (моно, края обрезает `silenceremove`), секции-паузы без голоса пропускай, а старые TTS-файлы перенеси в `build/vo_tts/`. Если диктор поменял текст, поправь строки VO в `script.md` под фактически сказанное, иначе субтитры разойдутся с голосом. Имена, латиницу и цифры оставляй как в сценарии. Ролик обычно становится длиннее: всё, что в `scenes.js` и `audio.py` завязано на абсолютные секунды, переведи на `WT()` / `B[]`.

### D. «Глянь правки сценария» / «проверь сценарий»
Правки со страницы раскадровки `src/script.html` лежат в `review/script_notes.md` (данные — `script_notes.json`); текст сцен пользователь правит там же, и он сразу пишется в `script.md`. Поэтому **перед правкой всегда перечитывай `script.md`**: там могут быть свежие ручные изменения, их нельзя затирать.
1. Прочитай `review/script_notes.md` (или `python review_server.py script-list`). У заметки есть тип, сцена, поле и выделенный фрагмент. «Весь сценарий» — общая правка (структура, тон, порядок, длина): её делай прямо в `script.md` и отвечай, что изменил. Если правок много, сначала дай план. Картинки-референсы к заметке перечислены в строке «Референсы: review/refs/sN_k.png…», прочитай их через Read.
2. По типам:
   - **🔎 Фактчек**: проверь фрагмент по `refs/` (транскрипты, recap, кадры) и источникам сценария, при необходимости по интернету. Ответь таблицей «утверждение → вердикт ✅/⚠️/❌ → что на самом деле, со ссылкой на таймкод или источник». Если нужна правка текста, **предложи замену, а не вноси её сам**: `--field VO --from "точный старый кусок" --to "новый"`. Пользователь применит её кнопкой «Применить».
   - **✍️ Переписать**: предложи новый вариант заменой (`--from/--to`), в подаче гайда (`prompts/style-guide.md`). Если вариантов несколько, дай их списком в тексте ответа, а лучший — заменой.
   - **🎨 Картинка** и **💬 Заметка**: правь `script.md` сам (Картинка, Текст, Кадры; можно менять порядок сцен и добавлять новые), затем ответь `--done`.
3. Ответ: `python review_server.py script-reply N "текст (markdown, таблицы можно)" [--done] [--field VO --from "…" --to "…"]`. **С заменой (`--from/--to`) не ставь `--done`**: закрытая заметка уходит во вкладку «сделанные», и пользователь не видит кнопку «Применить». Заметку закроет само применение. Никогда не перезаписывай `script_notes.json` целиком.
4. Если менялся текст VO: `python tts.py` (кнопка «🔊 Переозвучить» на странице делает то же самое), затем `python check_script.py` — ничего не должно уйти в ❌. Если ролик уже собран, дальше — как в B.6.

### «Хочу доточить звук в Premiere»
`python ../_pipeline/premiere_export.py` в папке проекта (после `./build.sh`) → `out/premiere/<проект>.xml` + `out/premiere/audio/*.wav`. В Premiere: File → Import → xml, откроется секвенция: видео без звука, голос хука, звериная речь, музыка и гул ламп (если `build_music(parts=True)`), каждый звук отдельным клипом (полосы без наложений, шаги отдельно), выключенный готовый микс для сравнения, маркеры сцен. Громкость вшита в клипы, фейдеры на 0 dB = ровно `build/mix.wav` (сверено суммой). Список дорожек — `out/premiere/дорожки.txt` (имена дорожек XML-импорт теряет). Правки из Premiere назад в пайплайн не возвращаются: финал экспортирует пользователь.

### E. Упаковка — всегда в конце, когда пользователь дал добро на ролик
Срабатывает на «всё ок», «норм, финал», «дай текст для озвучки» и похожие. Сделай оба пункта, не дожидаясь отдельной просьбы:
1. **Обложка** (1080×1920): сразу 3–4 варианта в `src/scenes.js`: `const THUMBNAILS = [{ draw(ctx) { … } }, …]` (один вариант — `THUMBNAIL`). Это отдельные кадры, а не стоп-кадры из ролика. Пользователю нравятся **яркие и чистые** обложки: однотонный насыщенный фон, одна крупная фраза в 2–4 слова (Rubik 900, толстая обводка), герой крупно с сильной эмоцией, минимум мелких деталей. Один вариант можно сделать «до / после». По карте превью «Мастер-планера» (Справочник «Штурма») целься в «золотой грааль»: для ёжика это «предмет и реакция» — он реагирует на саму вещь из новости; 1–3 образа, без ребуса. **Текст обложки не повторяет название**, а дополняет его (число, сумма или «СТОП» — уже образ). Если был штурм — первым вариантом сделай выбранную там связку. Важное держи в зоне y 150–1400: низ и правый край кадра в Shorts закрывает интерфейс. Субтитры на обложке не рисуются. Затем `node render.js thumb` → `out/thumbnail_N.png` + `.jpg`. Проверь картинку глазами (Read) и отправь её через SendUserFile.
2. **Тексты** в `out/packaging.md`: 5 вариантов названия (до ~50 знаков, лучший первым с пометкой, без спойлера главного поворота). Придумывай их через 4 угла атаки — число или сумма, сильный образ или эмоция, время или срочность, отрицание или противоречие — по 2–3 на угол, и в файл бери 5 самых сильных и разных. Дальше в том же файле — 3 описания (короткое для Shorts/Reels, с источниками, провокация для комментариев), закреп в комментариях, набор хэштегов, раздел «Права» (чьи кадры, логотипы и пародии вошли в ролик). Факты — только из сценария и его источников. Короткое описание и названия продублируй в чат.

### F. Итоги — после публикации
Когда пользователь говорит, что ролик вышел, или приносит цифры и комментарии, заполни его штурм (вкладка «Итоги»). Если штурма не было — заведи строку в «Просмотрах».
- **Работа над ошибками:** план и факт по часам, 5 вопросов, оценка «офигенно?» до цифр. Цифры по правкам даёт `📊 Цифры из проекта`: заметки ревью и сценария, дни от папки до сборки.
- **Реакция аудитории:** 5 комментариев.
- **Просмотры:** через 1 ч, сутки, 7, 14 и 28 дней, плюс доля не пролиставших и средний % просмотра из YouTube Studio. Пользователь вставляет цифры в чат или выгружает CSV.
- **Выводы** после 1-го, 3-го, 5-го и 10-го ролика: кнопка «✨ Выводы» в «Просмотрах» или сам. Что подтвердилось на своих цифрах, предлагай внести в `style-guide.md`: гайд собран по чужому каналу.

## Штурм идей — сервис по «Мастер-планеру»
Полная документация — `_pipeline/docs/`: `preproduction.md` (препродакшен: модель, черновики, 3D-редактор, ассеты, звуки, экспорт, план редактора сцены) и `shturm.md` (сервис целиком). Меняешь сервис — обнови их.
Локальная страница `http://localhost:8790/` (запуск — `Штурм идей.bat` в рабочей папке или `_pipeline/ideas.bat`; порт запущенного — `python _pipeline/ideas/ideas_server.py port`).
- **Два пути** (поле `flow` штурма), оба в двух режимах: ⚡ шортс и 🎬 длинное видео на 8–15 минут.
  - **«Есть идея»** (`flow: idea`, путь по умолчанию: «Новый шортс» / «Новое длинное»): идея + контекст + референсы (видео по ссылке или пути — `refvideo.py` режет контактные листы и расшифровывает речь; картинки) → **вопросы Claude** (15–20, потом уточняющие раунды; `qa[]`, ответы автора — его решения) → биты из ответов + **челлендж** (Claude-редактор: слабые места и новые вопросы) → смыслы и название (4 угла, без 7 вопросов) → **препродакшен** → обложка и первый кадр → в работу → итоги.
  - **«Штурм идей»** (старый путь, нет поля `flow`): идеи (10 → ★3 → ●1) → биты → название (7 вопросов, смыслы, 4 угла атаки, сильные слова) → образы (3 на смысл) → превью (одна связка; у шортса — «хук + первый кадр + обложка») → структура (схемы А/Б/В или три акта / инструкция) → в работу → итоги.
  - Плюс банк идей, лист проекта, трекер просмотров и справочник (карта превью, правила).
- **Препродакшен** — модель и экспорт в `_pipeline/ideas/preprod.py` (шапка файла — полная схема элемента). `elements[]`: `kind` char | prop | scene | sound — в таком порядке, `name`, `desc`, `why`, `status` '' | ok | drop, `refs[]` картинки автора; у сцены `uses[]` — id её персонажей и пропсов; `final[]` — «🎬 Для финала» {text, x?, y?}: что автор хочет от ассета в готовом ролике (у утверждённого клик по черновику ставит зелёный пин); у звука `mix[]` — слои ролика {sid, at, gain, note} + `mixNote` (`sound` = первый слой, для совместимости). **@-ссылки:** в любом поле страницы «@» открывает список элементов (↑↓, Tab/Enter — вставить), в текст пишется `@[Название]`; переименование элемента переписывает ссылки; упомянутые у сцены персонажи и пропсы входят в её состав; промпты (`preprod.element_brief`) и экспорт их раскрывают. **Сцены — после персонажей и пропсов:** «Что в сцене» связывает их со сценой, при рисовании сцены Claude получает их черновики и код `element.js` и ставит их в неё (в 3D — картонными карточками `w.card({draw: drawX…})`, ёжик — `hogCard`); «✨ Накидать» сам заполняет `uses` у новых сцен. **📦 Бесплатные ассеты** (карточка под референсами элемента, `assets.py`): поиск 3D (Poly Pizza, Poly Haven, Sketchfab, OpenGameArt), 2D (Openverse, Commons, OpenGameArt) и текстур (ambientCG, Poly Haven) без ключей; «✨ Подобрать» (`assets`, `ideas_claude.assets_spec`: Claude ищет через `assets.py search "q1" "q2" --kind …` с учётом «Что нужно» — `aask`) кладёт 3–6 предложений с объяснением в `picks[]` (строки поиска + `why`, `use` work|ref), ничего не скачивая — берёт автор; «📌 В реф.» кладёт превью в `refs[]`, «⬇ В работу» качает сам ассет в `files/<plan>/assets/<id>/` → `assets[]` (glTF, картинка, карты текстуры; лицензия и автор записаны), 🧊 — покрутить модель (`/tpl/stand3d.html?model=…&view=1`). Скачать со Sketchfab можно только с токеном пользователя в `_ideas/sketchfab_token.txt`. Claude при рисовании получает ассеты элемента и его состава (`preprod.assets_brief`): модели — через `MODELS` + `w.model`. «✨ Накидать» (`elements`, можно по типу и с подсказкой «чего не хватает») → у визуального элемента «🎨 Нарисовать черновик» (`element`, `ideas_claude.element_spec`): Claude пишет `_ideas/render/<plan>/<el>/vN/element.js` по контракту стенда (`PICS`, функция элемента, `ELEMENT.draw(ctx, T)`), рендерит `render_shot.js …&parts=element`, смотрит и правит; сцены при `engine: '3d'` — на 3D-стенде `/tpl/stand3d.html` (`world3d` шаблона). Правки — пины и «в целом» (`fx.main`: `notes[]` — по пункту на Enter, Backspace в пустом удаляет; старое одно поле `text` тоже читается), «Поправить» делает vN+1 от прошлого кода, отправленные пункты снимаются. 3D-черновик (`renders[].three`) смотрится живьём: «🧊 Смотреть в 3D» открывает `/tpl/stand3d.html?…&view=1` — сцена играет петлёй `ELEMENT.len` (по умолчанию 6 с), камера крутится мышью (свободная камера подменяет сценарную после `update` мира). «✋ Расставить» (там же «✋ Двигать», `&edit=1`): автор выбирает объект (клик или список `w.items`, объекты без `name` — «карточка 3» по порядку создания) и двигает его мышью по полу, Shift — по высоте, стрелки / PageUp / Q E / + − / H — сдвиг, поворот, размер, скрыть; в пределах ±12 м, ×0.25…4. Ctrl+клик — выбрать несколько (двигаются вместе), «🔗 Сгруппировать» / «⛓ Разгруппировать» (Ctrl+G / Ctrl+Shift+G), клик по части группы берёт группу, Alt+клик — часть; автогруппы можно разобрать. «💾 Сохранить» → `POST /api/layout3d` (задача `layout3d`, без Claude): новая версия черновика = тот же `element.js` + блок `// ==== расстановка автора` (`w.groups` + `w.layout`) в конце, кадры переснимаются, `renders[].layout`. «Поправить» от такой версии сохраняет блок (Claude закрепляет автоматические имена через `name`). Звук: «✨ Подобрать» (`sound`: Claude ищет через `sounds.py search` и в интернете, сервер скачивает 3–5 кандидатов в `files/<plan>/sfx/`), «🔎 Искать» (библиотека пайплайна, Freesound, Commons — без Claude), «⬇ по ссылке» (любая страница со звуком, прямой файл, YouTube через yt-dlp, «с/по» — кусок). ✓ у кандидата — выбранный звук. Нарисованные элементы Claude берёт в «🎨 Отрисовать» обложки.

## Устройство сервера ревью
`review_server.py` — тонкое ядро (порт, запуск, CLI), его почти не трогаем. Вся логика (заметки, `/sfxlib/`, описания правок в notes.md) лежит в `review_api.py`, раскадровка сценария (`/api/script*`, `/api/frame`, заметки сценария, запуск tts, CLI `script-*`) — в `script_api.py`. Страница ревью по умолчанию **играет собранное видео** `out/*.mp4` (`/api/video` + отдача с Range, чтобы работала перемотка) — 3D-сцены вживую в браузере лагают. Кнопка «🎞 видео / ⚙ живой» переключает на живую отрисовку кадров, чтобы видеть правки до пересборки; если код сцен новее видео, кнопка оранжевая. После правок пересобирай видео (`./build.sh`), иначе в режиме видео их не видно. Картинки-референсы к заметкам обеих страниц принимает `POST /api/ref` в `review_api.py` (файлы в `review/refs/`, пути в поле `refs` заметки), общий виджет вставки — `src/refs.js`. Оба модуля **перезагружаются на лету** при изменении файла. Если меняешь то, от чего зависит страница, подними `API_VERSION`: страница со старым сервером покажет плашку «перезапусти review.bat».

## Раскладка кадра 1080×1920
- Субтитры: центр по y ≈ 1470 (`H*0.765`). Зона y 1400–1540 должна быть свободна от важного.
- Заголовочная плашка сцены: y ≈ 170–250. Главное действие: y 400–1350.
- Держи отступ по бокам ≥ 60 px. Фоны, холмы, сетки рисуй шире кадра (камера отъезжает — края не должны показаться).

## Грабли, на которые уже наступали
- **Составные пути и правило nonzero**: если часть фигуры (хвост, ухо) нарисована в обратном направлении, при заливке в месте перекрытия появится дыра. Все подпути одной фигуры веди по часовой стрелке.
- **Пиксель-арт** (кадры игр, спрайты): `ctx.imageSmoothingEnabled = false`.
- **Переход** задаётся на ВХОДЯЩЕЙ сцене (`trans`). Точка нырка для `zoom` — `zoomAt` на ВЫХОДЯЩЕЙ. Кривые или диагональные переходы пользователю не нравятся — предпочитай `slide`, `zoom`, `iris`, `push`.
- **Короткие вставки**: если событие привязано к слову ближе к концу фразы, оно может провисеть меньше секунды. Проверяй длительность и начинай раньше, опираясь на предыдущие слова.
- **`WT(i, 'ключ')`** находит ПЕРВОЕ слово, содержащее подстроку. Бери уникальные куски слов.
- Пользователь любит **узнаваемую конкретику**: реальные кадры и спрайты, логотипы, отсылки к эпохе. Общая абстракция нравится меньше.
- Персонажи не должны перекрывать лица плашками и лапками. Руки у ёжиков растут из боков.
- Если с текстом не справляется edge-tts — у `tts.py` есть ретраи. `No audio received` — временный сбой.

## Где брать ассеты (пользователь разрешил скачивать)
Пользователь хочет, чтобы для эффекта ассеты качались без лишних вопросов. Подтверждение на скачивание всё равно нужно, поэтому собирай все файлы в ОДИН короткий вопрос (имя · источник · размер) и параллельно продолжай остальные правки.
- Логотипы: Wikimedia Commons, `https://commons.wikimedia.org/wiki/Special:FilePath/<File_name>` (+ поиск через `w/api.php?action=query&list=search&srnamespace=6`).
- Спрайты ретро-игр: The Spriters Resource (`/media/asset_icons/…png` — готовые кропы, `/media/assets/…png` — листы).
- Карты игр: snesmaps.com / nesmaps.com.
- Шрифты: `assets/fonts` (Rubik, Nunito, Press Start 2P — с кириллицей).
- Всегда говори пользователю, какие сторонние материалы (кадры, логотипы, спрайты) вошли в ролик: права на них у их владельцев.

## Инструменты
ffmpeg, Node 18+ (puppeteer-core ставится в проект при создании), Chrome или Edge (путь ищется автоматически, переопределяется через `CHROME=`), Python 3.10+ (edge-tts, numpy, pillow; faster-whisper — для своей озвучки). Рендер (`node render.js frames 60 6`, его вызывает `build.sh`): у каждой вкладки свой браузер (свой GPU-процесс), вкладки берут отрезки по 60 кадров, у кадра таймаут 30 с (зависший браузер перезапускается), каждые 900 кадров браузер обновляется. Кадры — JPEG q0.95, PNG был узким местом (27 против ~70 fps). Замер на 78-секундном шорте: кадры за 42 с (113 fps), вся сборка ~2 мин. Опции: `WORKERS=8`, `RENDER_FMT=png`, `RENDER_GPU=0` (программный рендер, ~54 fps), `RENDER_RANGE=a:b` (только часть кадров, для замеров). Не запускай сборку внутри команды с лимитом 10 минут: длинные ролики её перерастут. Для таких используй фоновый запуск.
