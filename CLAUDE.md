# Пайплайн вертикальных шортов (инструкция для Claude)

Рабочая папка (родитель `_studio/`, например `D:\work\Animations`) — это **Claude Studio**: каналы (папки с `channel.json`, первый — «Доедать будешь»), в каждом `videos/<Имя>/` — видео = проект ролика + `video.json` (бывший штурм). Приложение, движок и шаблон — `_studio/` (бывший `_pipeline`, связка `_pipeline` ведёт туда же; документация — `_studio/README.md`, план Studio — `_studio/docs/studio/`). В корне рабочей папки лежит `CLAUDE.md` с одной строкой `@_studio/CLAUDE.md`, так что эта инструкция подключается в любой сессии, открытой там. Архив (банк идей, старые штурмы, тестовые проекты) — `_archive/`, только чтение.
**Пути роликов ниже** («`ИИ пузырь/src/scenes.js`») — от папки видео канала: `Доедать будешь/videos/ИИ пузырь/src/scenes.js`. `chrono trigger/` — первый проект (птички, сделан до шаблона), образец богатых сцен.

Пользователь пишет по-русски, отвечай по-русски. Стиль по умолчанию: **бумажная аппликация** (коллаж). Фигуры вырезаны из бумаги, у них рваная кромка, зерно и тени; фото и логотипы вклеены вырезками с белой обводкой; надписи на тетрадных листках и от руки (шрифт Caveat); фон всё время слегка движется. Герой — **наш бумажный ёжик**, серый, из сотен рваных полосок, с тёмной маской, большими глазами и светлой мордочкой (в духе «Ёжика в тумане»). Он был во всех роликах начиная с PS6. **Не бери круглого ёжика в духе Смешариков из `src/chars.js`**: это старый стиль. Готовый код (набор `torn/cut/note/photo/sticker/label/scrawl` + `drawHog(ctx, x, yНог, рост, {kind: 'adult'|'kid'|'friend', look, lid, mouth, armL/armR, lenL/lenR, hoodie, cap, glasses, phones, beard, badge, wink, tired, prop})` + `aim()` для наведения лапы) копируй из последнего проекта: `ИИ пузырь/src/scenes.js` (там же гипно-волны, стикеры-цифры и переход `pop` в `main.js`). Палитру и фон подбирай под историю: серый туман (PS6), клетчатая тетрадь и крафт (ИИ пузырь), нуар и т.д.

## Где что лежит (скиллы и справочники)
Подробные инструкции вынесены из этого файла (16.10.2026), текст в них дословный. Исходники скиллов — `_studio/skills/<имя>/` (в git), в `.claude/skills/` рабочей папки — ссылки-junction на них; правь исходники. **Перед работой по сценарию ниже вызови скилл** (Skill) или прочитай файл:
- **Сценарий** («напиши сценарий», материалы / идея / штурм, «сценарий по видео X», правки сценария со страницы раскадровки) — скилл `shorts-script`. Шаги сценариста — `_studio/prompts/scriptwriter.md`, длинное — `prompts/longform.md`, гуманайзер — `prompts/humanizer/<lang>.md`.
- **Сборка ролика кодом** («сделай шорт по сценарию в папке X», `scenes.js`, звуки `lib:`, сервер ревью, `render.js snap`, `build.sh`, ассеты, инструменты рендера, anatomy-вставка) — скилл `shorts-build`.
- **Правки ролика** («глянь правки», `review/notes.md`, звуковые правки, Premiere) — скилл `review-edits`.
- **Своя озвучка** («подставь мою озвучку») — скилл `voiceover`.
- **Упаковка и итоги** («всё ок / финал» → обложки + `out/packaging.md`; «как зашёл ролик?» → `studio.py yt show`) — скилл `packaging`. Срабатывает сам, без отдельной просьбы.
- **3D** (stage3d.js, `world3d`, `hogCard`, `moves3d.js`, layout автора, glTF, сторож монтажа, линтер сцены) — скилл `stage3d`.
- **Игровой формат** (пародия на хоррор-игру, Silent Hill-диалоги, «звериная речь») — скилл `game-format`.
- **Claude Studio** (приложение `_studio/`, `studio.py`, `video.json`, препродакшен, сцены редактора, локации, монтаж, библиотека, луки, сценаристы, сценарии S33, агент, очередь, звук, телефон) — скилл `studio-app` (индекс + файлы по темам). ТЗ этапов — `_studio/docs/studio/stageN-*.md`.
- **Схема «как это устроено»** (разрез, изометрия механизма) — скилл `anatomy`; как вставлять в ролик — в `shorts-build`. `publish.mjs --submit` — только по слову автора.

## Жёсткие правила (кратко; подробности — в скиллах)
- **Писать в видео из сессии — только через CLI** `python _studio/server/studio.py …`, JSON руками не править (страница держит документ открытым). Сцены редактора — только `scene ops`; ручные правки автора (`authored`, 🔒 `by: author`) не трогать без его «да».
- **Сгенерированный `src/scenes.js`** (монтаж Studio) руками не править — правь `video.json → montage` и `montage gen`.
- **По умолчанию:** препродакшен утверждён → монтаж на локациях; ⚡ быстрый монтаж — не по умолчанию. Персонаж в 3D — настоящий объём (Blender), бумажная карточка — только если автор сказал. Слова автора главнее стиля канала.
- **«Уже было» (S15):** `add-elements` без `--no-reuse`; решение `lib reuse` — только по слову автора. Образ того же героя — `--variant-of`, не новый персонаж.
- **Звук:** всё, что звучит, — плашкой на таймлайне (вжух перехода — дорожка «Переходы», без скрытых звуков в коде). mp4 «⚠ старее монтажа» не показывать как готовый — экспорт заново.
- **После 3D-правок** — `montage guard` и `scene lint`, каждое ❌ чинить. Вход / уход объектов — `life3` / `enter3` / `exit3`, а не `visible`.
- **Сценарий:** длины и таймкодов в S33 нет (`### Название`, `**Пауза:** N`); подача — по референсу и гуманайзеру, не по старому стайл-гайду; факты — только из источников. Есть утверждённая карта подачи — `beatmap show` и писать по ней.
- **Пиксельный ёжик** (`pixelHogCard`) и круглый ёжик из `src/chars.js` — не использовать. Монстров старыми гравюрами не делать.
- **Ассеты** качать для эффекта можно, но все файлы — одним коротким вопросом (имя · источник · размер). Всегда говори, какие чужие материалы вошли в ролик.
- **Приложение:** меняешь Studio — обнови `_studio/docs/studio/` и справочник `_studio/skills/studio-app/`; при изменении страницы поднимай `API_VERSION`. Иконки — `Icon()` / `EMOJI_ICON`, не эмодзи в разметку. Новые опросы — `StudioIdle.every`, не голый `setInterval`. `master-planer.pdf` не цитировать и в репозиторий не класть.
- **Сборка:** долгие сборки (`build.sh`, экспорт) — в фоне, не внутри команды с лимитом 10 минут. `build.sh` — только Git Bash.

## Раскладка кадра
**Длинное 16:9 (1920×1080, `WIDE`):** субтитры внизу (y ≈ 0,86 H, до 6 слов), плашки сцен — сверху (y ≈ 110–190), главное действие — центральные 60 % ширины и y 180–860, отступ по бокам ≥ 90 px; используй ширину — две вещи рядом, панорамы. Карточка главы — на первые ~2 с первой сцены главы.
Рендер длинного: 30 fps (в «Экспорте» по умолчанию), `render.js` кэширует кадры по сценам (`build/segcache/<fps>_<подпись>.h264`, две последние сборки на каждую частоту): правка сцены перерендеривает только её куски и переходы, сбой или отмена — продолжение с готовых кусков (`RENDER_FRESH=1` — с нуля). Подпись куска — общий код + код его сцены (файл `src/scenes/sNN.js` с `SCENES[k] =` или юнит монтажа) + её время и слова; связи сцен (общие имена в файлах сцен, `SCENES[n]`, `paperTurnIn`) находятся по коду и пишутся в лог. Общий код (`scenes.js`, движок, черновики) — полный рендер, при экспорте — `out/<имя>_chapters.txt` и главы в `<имя>.txt`.

**Шортс 1080×1920:**
- Субтитры: центр по y ≈ 1470 (`H*0.765`). Зона y 1400–1540 должна быть свободна от важного.
- Заголовочная плашка сцены: y ≈ 170–250. Главное действие: y 400–1350.
- Держи отступ по бокам ≥ 60 px. Фоны, холмы, сетки рисуй шире кадра (камера отъезжает — края не должны показаться).

## Грабли, на которые уже наступали
- **Составные пути и правило nonzero**: если часть фигуры (хвост, ухо) нарисована в обратном направлении, при заливке в месте перекрытия появится дыра. Все подпути одной фигуры веди по часовой стрелке.
- **Пиксель-арт** (кадры игр, спрайты): `ctx.imageSmoothingEnabled = false`.
- **Переход** задаётся на ВХОДЯЩЕЙ сцене (`trans`). Точка нырка для `zoom` — `zoomAt` на ВЫХОДЯЩЕЙ. Кривые или диагональные переходы пользователю не нравятся — предпочитай `slide`, `zoom`, `iris`, `push`.
- **Короткие вставки**: если событие привязано к слову ближе к концу фразы, оно может провисеть меньше секунды. Проверяй длительность и начинай раньше, опираясь на предыдущие слова.
- **`WT(i, 'ключ')`** находит ПЕРВОЕ слово, содержащее подстроку. Бери уникальные куски слов.
- Пользователь любит **узнаваемую конкретику**: реальные кадры и спрайты, логотипы, отсылки к эпохе. Общая абстракция нравится меньше.
- Персонажи не должны перекрывать лица плашками и лапками. Руки у ёжиков растут из боков.
- Если с текстом не справляется edge-tts — у `tts.py` есть ретраи. `No audio received` — временный сбой.
